# SKYFALL ARENA

웹 브라우저용 영웅 기반 하이퍼 FPS. 싱글 플레이, AI 봇 웨이브 섬멸전.
기획은 [GDD.md](GDD.md) 참고.

**플레이:** https://sena980909.github.io/skyfall-arena/  (GitHub Pages, 데스크톱 Chrome/Edge 권장)

## 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5179 접속. **Pointer Lock(마우스 잠금)이 필요하므로 일반 Chrome/Edge 탭에서 실행**해야 마우스 시점이 동작한다 (임베디드 브라우저 패널에서는 시점 회전 불가).

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 (HMR) |
| `npm run typecheck` | 타입 체크 |
| `npm run build` | 타입 체크 + 프로덕션 빌드 (`dist/`) |

- 효과음을 힉스필드(Mirelo SFX)로 생성해 `public/assets/sfx/`에 배치 (2차: 미래풍·부드러운 합성음으로 재생성, WebAudio 분석으로 거친/무음 클립 걸러 14종 채택, 6종은 합성음 유지). 뱅크 버스에 컴프레서, 클립별 RMS 정규화(목표 0.2)·가장자리 페이드, 마스터 0.28. 사실상 무음인 생성 클립(rms<0.02)은 로드 시 자동 제외되어 합성음으로 폴백. `game.sfx.bank.report(0.28)`로 클립별 출력 dBFS 확인 가능.

## 레이븐 키트 (돌격형 · 솔저 계열 구성)

| 키 | 스킬 | 수치 |
|---|---|---|
| 좌클릭 | 펄스 라이플 | 18 피해, 초당 9발, 30발, 헤드샷 ×2 |
| Shift | 달리기 | 이동 1.5배, 사격·로켓 사용 시 해제 |
| 우클릭 | 펄스 로켓 | 나선 3연 에너지탄, 직격 40 + 스플래시 80(반경 3m, 가장자리 50%), 쿨 6초 |
| E | 치유 필드 | 발밑 설치, 반경 4.5m, 초당 35 회복, 5초, 쿨 15초 |
| Q | 전술 조준 | 6초간 화면 안 적 자동 조준(몸통 판정), 발동 시 즉시 재장전 |

메커니즘 구성은 돌격형 영웅 아키타입을 따르되 이름·외형·사운드는 오리지널이다.

1인칭 뷰모델(`public/assets/models/fp_arms.glb`): 레이븐 컨셉(`assets/concept/raven_concept.png`)과 펄스 라이플 컨셉을 레퍼런스로 넣어 '주인공의 양팔이 라이플을 겨눈' 이미지(`assets/concept/fp_arms_concept.png`)를 만들고 image_to_3d로 변환한 단일 메시(30k tris, WebP 1K, 1.65MB). 왼손은 총열덮개를 아래에서 받치고 오른손 검지는 방아쇠, 전완은 팔꿈치까지 길어 절단면이 화면 밖에 있다. 전완 끝은 안으로 패인 컵 모양이라, 가장 낮은 정점 덩어리(왼팔 끝)와 총 아래 가장 뒤쪽 덩어리(오른팔 끝)를 찾아 관절 구로 막고 어깨(카메라 아래·뒤 양쪽) 방향으로 상완 원통을 이어 붙여(`ArmSleeves.ts`) 총을 들어도 빈 공간이 보이지 않고, 모델을 1.25m 길이(기존 0.92)로 36% 키우고 뷰모델을 올려 총구를 7° 들어 전완 장갑이 화면 하단에 크게 보이게 해 손·총이 공중에 뜬 인상을 없앴다. 정렬은 `alignGunUpright`(GunAlign.ts): 생성 모델의 +Y를 그대로 '위'로 두고 총 부분(모델 위쪽 절반)의 수평 주축으로 요만 -Z에 맞춘다. 메시 전체 PCA로 '위'를 추정하던 이전 방식은 팔 때문에 총이 10~30° 롤된 채 놓였다. 월드와 분리된 전용 FOV(`Player.VIEWMODEL_FOV`=56)로 2패스 렌더하고, 궤적·섬광·로켓 출발점은 두 FOV 차이를 보정한 총구 위치(`fxMuzzlePosition`)를 쓴다. 걸음 8자 흔들림, 옆걸음 기울임, 착지 반동, 숨쉬기, 반동 모션에 더해 질주 시 아래·안쪽 캐리 자세로 블렌드. 재장전은 총을 들어 올리지 않고 안쪽으로 굴리며 몸쪽으로 당기는 모션이다(뷰모델 피벗이 카메라 근처라 총구를 들면 카메라 앞 전완 절단면이 화면으로 올라온다).

탄환·섬광 VFX: 탄환 광선은 십자 평면 대신 매 프레임 카메라를 향해 축 회전하는 한 장의 리본으로, 꼬리가 총구에서 시작해 앞으로 자라며 총구 근처에서 페이드인(총구 바로 앞에서 세로 막대처럼 보이던 문제 제거). 섬광·탄환 텍스처는 힉스필드(gpt-image)로 재생성한 뒤 `tools/vfx-prep.mjs`(sharp)로 검정 배경 평탄화·중앙 크롭·가장자리 마스크를 적용해 가산 합성 시 스프라이트 사각 경계가 비치지 않게 했다.

사망 연출: 플레이어가 죽으면 카메라가 가속하며 맞은 쪽 반대로 기울어 바닥(눈높이 0.32m)까지 쓰러지고 살짝 튕긴 뒤, 1.4초에 걸쳐 처치자 쪽으로 고개가 돌아간다(`Player.updateDeathCam`). ELIMINATED 오버레이는 0.6초 뒤 얇은 붉은 비네트로 덮여 쓰러지는 장면이 보인다. 봇은 생성된 death 클립이 끝까지 서 있는 불량 클립이라, 피격 반대 방향으로 나무 넘어지듯 가속 회전해 눕고(0.55초) 0.9초 뒤 디졸브하는 절차적 넘어짐을 쓴다(`Bot.updateDeath`).

입력: 키 '방금 눌림'은 시뮬레이션 스텝이 소비한 뒤에만 지운다. 렌더 프레임마다 지우던 이전 방식은 스텝이 없는 프레임(고주사율 모니터)에서 점프·스킬 입력을 유실했다.

봇 교착 수정: (1) 경로 시작/목표 셀을 에이전트가 실제로 선 높이의 셀로 고른다(플랫폼 가장자리에 걸친 봇을 지면 셀로 잡으면 난간 너머로 가라는 경로가 나와 영원히 끼임). (2) 낙하 노드는 가장자리 너머로 0.6m 밀어내고, 실제로 내려간 뒤에만 도착 처리한다. (3) 플레이어가 교전 거리의 1.3배 밖이면 엄폐 대신 접근한다(멀리서 숨었다 쏘기 반복 교착 방지). (4) 경로 추종 중 2.2초 이상 완전히 멈추면 같은 높이의 근처 지점으로 우회.

봇 애니메이션 보정: 생성된 shoot/aim 클립은 왼손이 총을 잡지 않고 옆으로 뻗어 있고, aim 클립은 재생 중 상체가 130° 이상 돌아간다. 정지 사격·조준 대기에는 shoot 클립만 쓰고, 왼팔에 2본 IK(`Bot.solveLeftArmIK`)를 걸어 왼손이 항상 총열덮개(홀더 −Z 0.3m)를 잡게 했다. 1인칭 로켓 반동은 총구를 들어 올리는 대신 뒤로 밀어 전완 절단면이 보이지 않게 했다.

캐릭터 덩치 보정: 생성된 레이븐 모델은 컨셉·1인칭 팔보다 견장과 전완 장갑이 작게 나와, 어깨 본 1.35배(상완 역스케일로 팔 길이 유지)·전완 두께 1.3배(손 역스케일)를 매 프레임 적용한다(`Bot.applyArmorBulk`). 모델 재생성 없이 실루엣을 컨셉에 맞춘다.

봇 이동 애니메이션(문워크·머리 숙임 수정): 원인은 걷기 클립이 없어서 (1) 교전 중 옆걸음에 웅크린 사이드스텝 클립(머리 61° 숙임, 머리 높이 1.15m)을 이동 시간의 76% 동안 썼고 (2) 발 접지 속도가 0.26~0.89m/s인 클립을 2.6~4.7m/s 이동에 재생해 발이 미끄러졌기 때문이다. 수정: 다리(그룹)는 항상 실제 이동 방향을 보고, 교전 중 상체는 척추 3본 비틀림으로 조준 방향을 본다(`Bot.applyTorsoTwist`). 조준 반대로 물러날 때는 다리를 이동 반대쪽으로 돌리고 뒷걸음 클립을 쓴다(110°/80° 히스테리시스). 힉스필드로 걷기(Quick_Walk)·뒷걸음(Walk_Backward_with_Gun) 클립을 추가 생성했고, 재생 속도 = 이동 속도 / 클립의 발 접지 속도(`CLIP_SPEED`: 달리기 5.6, 걷기 1.55, 뒷걸음 1.43m/s, 브라우저에서 발 본으로 실측). 루트가 전진하는 클립은 로드 시 Hips 수평 이동분을 제거한다(`stripRootMotion`). 총은 교전 시 손이 아니라 목 기준 견착 위치에 고정하고 양팔 IK로 손을 총에 붙여, 달리기 클립의 팔 휘두름에 총이 끌려다니지 않는다. 웅크린 strafe 클립과 상체가 돌아가는 aim 클립은 더 이상 쓰지 않아 삭제했다.

봇 상체 빙글빙글 회전 수정: 척추 비틀림·팔 IK는 본 회전에 '덧붙이는' 방식인데, 믹서가 가중치 0인 순간 등 일부 프레임에 본 회전을 덮어쓰지 않아 덧붙인 회전이 누적됐다(배포본 실측: 봇 23기 중 18기가 1초 안에 상체 360° 이상 회전, 다리 대비 누적 8826°). 수정: (1) 매 프레임 믹서 갱신 전에 클립 원본 회전으로 복원하고 갱신 후 다시 저장(`Bot.updateMixer`), (2) 클립 가중치를 직접 관리해 합이 항상 1(`updateAnimWeights`, 기본 fadeIn/fadeOut은 빠른 전환 시 합이 1 미만이 되어 바인드 포즈가 섞임), (3) 상체 요를 월드 기준으로 따로 두고 각속도 제한으로 조준을 따라가며 비틀림은 연속값으로 갱신, (4) 이동/정지·전진/뒷걸음·클립 전환에 최소 유지 시간. 수정 후 같은 측정에서 360° 회전 0기, 누적 최대 145°.

### Blender 에셋 파이프라인 (v2, B0~B1 완료)

1인칭 팔+라이플은 이제 Blender에서 Python으로 직접 모델링·리깅·애니메이션한 리그(`public/assets/models/fp_rig.glb`, 17.3k tris, 본 39개, 0.95MB)를 쓴다. 이미지→3D 덩어리 메시(`fp_arms.glb`)는 새 리그가 없을 때만 내려받는 폴백이다.

- 소스: `tools/blender/lib_build.py`(프리미티브·베벨·리지드 스키닝 도구), `fp_rifle.py`(도면 픽셀 좌표로 만든 펄스 라이플), `build_fp_rig.py`(팔·손가락, 2본 IK 해석해로 포즈 계산, idle·reload 클립 베이크, GLB 내보내기). 결과 `.blend`는 `assets_src/fp_rig.blend`.
- 리그 공간 = 카메라 공간(원점이 눈, 정면 -Z)이라 뷰모델 원점에 그대로 붙는다. 방향 추정·롤 보정·절단면 메우기가 필요 없다.
- 팔은 어깨 뒤까지 모델링되어 어떤 화면비에서도 잘린 단면이 보이지 않는다. 손가락은 관절 3개씩 본이 있어 손잡이·총열덮개·탄창을 실제로 쥔다.
- 재장전 클립(총을 기울여 탄창을 빼고 새 탄창을 꽂음)은 무기의 재장전 진행도에 클립 시간을 직접 맞춰 재생한다(`Player.updateFpRig`).
- 다시 만들기: `blender -b --factory-startup --python tools/blender/build_fp_rig.py -- <프로젝트 절대경로>` (미리보기 렌더만: 끝에 `preview_only`).
- 참고 도면은 힉스필드로 생성(`assets_src/reference/`).

### Blender 에셋 파이프라인 B2: 적 봇 리그

적 봇도 Blender에서 직접 만든 리그(`public/assets/models/bot_rig.glb`, 10.9k tris, 본 11개, 클립 5개, 0.91MB)를 쓴다. 새 리그가 있으면 이전 에셋(raven.glb, 라이브러리 클립, pulse_rifle.glb)은 내려받지 않는다.

- 소스: `tools/blender/build_bot_rig.py`(몸·다리 모델링, 보행 생성, 굽기), `arm_lib.py`(팔·손 공용 모듈). 결과 `.blend`는 `assets_src/bot_rig.blend`.
- 본 구조: hips → torso → (head, armsgun → muzzle), 다리 6본. 팔과 라이플은 조준 자세 그대로 armsgun 본 하나에 묶여 있어 손이 총에서 떨어질 수 없다. 게임은 torso를 돌려 상체를 조준 방향으로 틀고(`applyTorsoTwist`), armsgun을 어깨 축으로 돌려 상하 조준과 로우레디를 만든다(`applyAimPitch`). 게임 쪽 IK·총 부착·장갑 확대 코드는 새 리그에서 쓰지 않는다.
- 이동 클립(walk 1.6 / jog 2.8 / run 4.7 / back 3.2 m/s)은 제자리 클립이고, 접지한 발이 정확히 그 속도로 뒤로 움직이도록 다리를 IK로 계산해 구웠다. 게임은 속도에 가장 가까운 클립을 골라 재생 속도 = 이동 속도 / 클립 속도로 맞춘다.
- 옆걸음 방향을 뒤집을 때는 다리를 180° 돌리지 않고 앞걸음/뒷걸음만 바꾼다.
- 실측(NORMAL 오토파일럿 한 판, 봇 23기): 접지한 발의 미끄러짐 중앙값 run 0.00 / jog 0.02 / back 0.06 / walk 0.22 m/s, 1초 안에 상체가 360° 넘게 돈 봇 0기.
- 재질 이름으로 팀 색을 입힌다: `bot_armor`·`armor_blue` = 팀 색(일반 주황, 보스 빨강), `bot_visor` = 바이저, `*glow*` = 발광.

### Blender 에셋 파이프라인 B3: 맵 모듈 키트

맵 외형도 Blender에서 만든 모듈 키트(`public/assets/models/map_kit.glb`, 모듈 14종, 7.4k tris, 0.49MB)로 바꿨다. 소스는 `tools/blender/build_map_kit.py`, 결과 `.blend`는 `assets_src/map_kit.blend`.

- 모듈: 컨테이너 4색, 크레이트 2종, 엄폐 방벽, 중앙 플랫폼(상판·기둥·난간·계단), 외벽 구간, 배경 타워, 벽 위 조명.
- 충돌 상자와 탄 판정용 메시는 그대로 두고 보이지 않게만 한 뒤(`GreyboxMap.applyKit`), 모듈을 상자 크기·방향에 맞춰 얹는다. three.js 레이캐스트는 visible을 보지 않으므로 판정·봇 시야·길찾기는 바뀌지 않는다.
- 색은 정점 색으로 구워 모듈당 재질이 1~3개(kit_paint + 발광)다. 표면 디테일은 아래 디테일 텍스처로 입힌다.
- 배경 타워 13개와 벽 위 조명은 경기장 밖·벽 위에 있어 충돌과 판정이 없다.
- 측정: 시작 지점 기준 드로콜 338, 삼각형 9.4만(월드+그림자+뷰모델). NORMAL 오토파일럿 한 판 승리, 명중률 55%로 이전과 같음.

### 디테일 텍스처 (힉스필드 생성 → 맵·봇·1인칭 리그)

단색이던 Blender 모델 세 종에 힉스필드로 만든 타일형 디테일 텍스처를 입혔다.

- 원본: `assets_src/textures_raw/`(패널 2종, 슈트 육각 직조, 벗겨진 도장). 게임용: `public/assets/textures/detail_{panel,suit,worn}.jpg`.
- 후처리 `node tools/tex-prep.mjs <원본.png> <결과.jpg> [크기] [평균 밝기] [대비]`: 회색조로 바꾸고 평균 밝기를 맞춘다. 텍스처는 색이 아니라 명암만 담고, 게임에서 재질 색·정점 색 위에 곱해진다. 그래서 팀 색 변경과 피격 점멸이 그대로 동작한다.
- UV: Blender 빌드에서 상자 투영 UV를 넣는다(`lib_build.box_uv`, 1칸 = 1인칭 리그 0.22m, 봇 0.45m, 맵 2.5m). 텍스처는 거울 반복이라 이음새가 없다.
- 적용: `Assets.applyDetailTextures`가 재질 이름으로 고른다. 맵 도장(`kit_paint`)은 벗겨진 도장, 슈트·장갑은 육각 직조, 나머지 장갑·총기는 패널. 발광·바이저 재질은 제외. 같은 텍스처를 bumpMap으로도 써서 패널 선에 음영이 생긴다.
- 검은 재질(총 몸통·총열, 봇 관절)은 어두운 선을 곱해도 보이지 않는다. 그래서 명암을 뒤집은 `detail_panel_dark.jpg`(`tex-prep.mjs ... invert`)를 쓰고 재질 색을 3.8배 밝혀, 바탕 밝기는 그대로 두고 패널 선만 밝게 띄운다(`DARK_MATERIAL`, `DARK_GAIN`).
- 2차 조정: 대비를 패널 1.0→1.5, 도장 1.6→2.2, 슈트 1.0→1.5로, bumpScale을 0.9/0.8/0.4로 올렸다.
- 검증: 타입 검사 통과, 재질 13종에 텍스처 적용 확인, NORMAL 오토파일럿 한 판 승리(명중률 54%, 이전 55%), 콘솔 오류 없음.

### 효과음 4차: 재장전 단계별 동기화 + 발소리·착지 클립

- 재장전음을 세 단계로 나눠 1인칭 재장전 애니메이션의 동작 시점에 낸다(`Player.RELOAD_CUES`, `Sfx.reloadStage`). 탄창 분리 0.14초, 새 탄창 삽입 0.93초, 왼손 복귀 1.15초. 이전에는 시작할 때 한 번에 재생해 삽입음이 0.62초에 나서 화면(0.93초)과 어긋났다.
- 힉스필드(Mirelo SFX)로 발소리·착지·탄창 분리·삽입음을 새로 만들었다. 18개를 만들어 WebAudio 분석(피크, 소리 구간, 잡음 바닥)으로 8개를 골랐다. 나머지 10개는 거의 무음이거나 저음 웅웅거림이라 버렸다. 원본은 `assets_src/sfx_raw/`.
- 발소리 4종, 착지 2종은 재생할 때마다 직전과 다른 것을 무작위로 고른다. 플레이어 발소리, 봇 발소리(3D 위치), 착지에 쓴다.
- `manifest.json` 항목이 파일명 외에 `{ file, from, to }`와 배열을 받는다. 생성 클립은 1초 안에 소리가 뒤쪽에 있거나 여러 번 나서, 필요한 구간만 잘라 쓰고 구간 안의 첫 소리 지점까지 앞 무음을 걷어낸다(`AudioBank.cut`).
- 합성음은 그대로 바탕으로 두고 클립이 있을 때 0.6배로 줄여 겹친다. 장전 완료음(3단계)은 생성 결과가 쓸 만하지 않아 합성음만 쓴다.
- 검증: 오토파일럿 한 판에서 재장전 18회의 단계별 재생 시점이 클립 시각 0.13 / 0.92 / 1.13~1.15초, 발소리 클립 1,118회, 착지 3회 재생, 콘솔 오류 없음. 소리의 질감은 사람 귀로 확인이 필요하다(자동 검증은 파형 분석까지).

### 화면 연출: 후처리·조명·탄흔

- 후처리(`src/render/PostFx.ts`): 월드와 1인칭 뷰모델을 각자의 렌더 타깃에 그려 합친 뒤 블룸 → 톤매핑·sRGB → 화면 보정 순으로 처리한다. 화면 보정은 비네트, 분할 톤(밝은 곳 따뜻하게·어두운 곳 차갑게), 약한 대비 상승, 필름 그레인, 가장자리 색수차.
- 뷰모델을 별도 타깃에 그리는 이유: 멀티샘플 타깃에 지우지 않고 두 번 그리면 첫 번째 그림(월드)이 보존된다는 보장이 없다. 뷰모델 타깃은 투명 배경으로 지우고 셰이더에서 월드 위에 덮는다. 안티에일리어싱은 타깃의 4배 멀티샘플을 쓴다.
- 피격 반응: 맞은 만큼 색수차와 붉은 가장자리가 순간적으로 강해진다. 체력이 35% 아래로 내려가면 채도가 빠지고 가장자리가 붉게 뛴다.
- 조명: 해를 낮고 따뜻하게(세기 1.8→2.7), 하늘빛을 약하게(0.9→0.62) 바꿔 볕과 그늘의 대비를 키웠다. 노출 1.05→1.22, 안개 시작 거리 120→60m.
- 탄흔(`Fx.decal`): 탄이 맵에 맞으면 그을음 자국이 남고 달아오른 점이 0.7초 동안 식는다. 최대 48개를 돌려쓰고 9초 뒤 사라진다. `hitscan` 결과에 표면 법선(`normal`)을 추가했다.
- F7로 후처리를 켜고 끈다. 플레이 첫 240프레임의 평균이 40fps에 못 미치면 자동으로 끄고 알림을 띄운다.
- 측정(내장 브라우저, RTX 4060, 966×846): 후처리 켬 158fps, 끔 164fps. NORMAL 오토파일럿 한 판 승리(명중률 60%), 콘솔 오류 없음. 저사양 그래픽 기기에서의 프레임은 측정하지 못했다.

### 적 봇 상세 모델 (힉스필드 이미지→3D + 기존 리그)

적 봇의 겉모습을 힉스필드로 만든 상세 메시로 바꿨다. 본·애니메이션·게임 로직은 직접 만든 리그 그대로다.

1. 현재 절차 모델을 정면·좌측·후면 직교 뷰로 렌더한다(`tools/blender/render_bot_views.py` → `assets_src/reference/bot_view_*.png`).
2. 그 렌더를 자세·비율 기준으로 넣어 상세 디자인 이미지를 만든다(GPT Image 2.6, 3장, `assets_src/higgs/bot_detail_{front,left,back}.png`). 자세가 리그와 같아야 하므로 새 자세를 그리게 하지 않고 기존 모델을 '다시 디자인'하게 한다.
3. 세 장을 Tripo H3.1 멀티뷰 이미지→3D에 넣어 GLB를 받는다(`assets_src/higgs/bot_detail.glb`, 19k tris, 텍스처·PBR 포함, 9 크레딧).
4. `tools/blender/bot_detail.py`가 상세 메시를 절차 메시에 정렬하고(90도 단위 회전 4가지 중 최적 + 이동·배율 보정, 평균 오차 1.3cm), 각 정점에서 가장 가까운 절차 메시 면의 본을 물려받게 한 뒤 관절 경계의 가중치를 이웃과 섞는다. 바이저 면은 `bot_visor` 재질로 나눠 게임이 색·발광을 바꿀 수 있게 한다.
5. `build_bot_rig.py`는 `assets_src/higgs/bot_detail.glb`가 있으면 자동으로 상세 메시를 쓴다. 인자에 `no_detail`을 주면 절차 모델로 빌드한다.

- 결과: `bot_rig.glb` 1.40MB(텍스처 1024 JPEG 3장), 삼각형 10.9k → 19.2k, 본 11개·클립 5개는 동일.
- 게임: 자체 텍스처가 있는 재질에는 디테일 텍스처를 덮지 않는다. 보스는 텍스처 위에 붉은 색을 곱한다.
- 검증: NORMAL 오토파일럿 한 판 승리(명중률 63%), 콘솔 오류 없음. 상체 회전 측정은 배포본(이전 모델)과 같은 범위였다(1초 안에 한 바퀴 넘게 도는 봇이 판마다 0~3/23, 모델 교체와 무관한 기존 수치).

### 주인공 상세 모델: 3인칭 몸 + 1인칭 팔·총

주인공은 적과 같은 상세 모델의 파란색 판이다. 3인칭 몸과 1인칭 팔·총을 같은 디자인·같은 총 쥐는 자세에서 만들었다.

- **3인칭 몸** (`player_rig.glb`, `build_bot_rig.py ... player`): 적 봇 리그에 팔 관절(상완·전완·손)과 총·탄창 본, 재장전 클립을 더했다. 색은 텍스처의 따뜻한 색을 파란색·청록색으로 바꿔 만든다(`bot_detail.recolor_blue`). 생성 메시는 손·총·가슴이 한 표면이라 재장전처럼 손이 총에서 떨어지면 그 사이가 길게 늘어난다. 그래서 따로 움직여야 하는 덩어리(왼팔 아래쪽 / 오른팔+총 / 몸)의 경계에서 메시를 잘라 떼어 놓는다(`swap_in(part_of, joined)`).
- **재장전 시간표 공유** (`tools/blender/reload_timeline.py`): 기울임, 탄창 분리, 새 탄창, 밀어 넣기, 왼손 복귀의 구간을 한곳에 두고 3인칭 클립·1인칭 연출·효과음 시점이 같이 쓴다. 3인칭에서는 왼손이 왼쪽 골반 앞 주머니에서 새 탄창을 꺼내 온다.
- **3인칭 시점** (V): 오른쪽 어깨 너머 카메라(옆 0.5m·위 0.15m·뒤 2.8m, 벽에 막히면 그 앞까지). 조준 광선은 카메라에서 조준점으로 나가되 몸 깊이에서 시작해 카메라와 몸 사이의 물체는 맞히지 않는다. 다리는 이동 방향, 상체는 조준 방향을 향하고 팔·총은 조준 피치만큼 돈다(`src/entities/PlayerBody.ts`). 사망하면 몸이 뒤로 쓰러진다.
- **1인칭 팔·총** (`fp_detail.glb`, `build_bot_rig.py ... fp`): 몸이 총을 든 자세에서 팔·총만 따로 상세 모델로 만들었다. 절차 모델의 팔·총을 정면·좌·후면으로 렌더(`... fpref`)해 자세 기준으로 쓰고, 같은 디자인의 파란색 확대 이미지 3장 → Tripo 멀티뷰(38k tris, 텍스처 2048)로 만든 뒤 절차 팔·총에 정렬한다(평균 오차 6mm). 눈이 원점이라 뷰모델에 그대로 붙이고 조준 높이까지 올려 놓는다.
- 1인칭 모델은 팔·총이 한 덩어리라 본 애니메이션이 없다. 재장전은 같은 시간표로 총을 기울여 화면 아래로 내렸다 올리고, 탄창이 걸리는 순간 살짝 튄다.
- 생성 모델의 거칠기 맵은 거의 거울 수준(평균 0.17)이라 가까이서 젖은 크롬처럼 보인다. 1인칭에서는 금속성 0.3·거칠기 0.55 고정에 노멀 맵만 쓴다.
- 전신 모델에서 팔·총만 잘라 1인칭에 쓰는 방법은 해상도가 모자라 뭉개져서 버렸다. Tripo의 텍스처 '상세' 옵션은 색 텍스처가 회색으로 비어 나와 표준 옵션으로 다시 만들었다.
- 화면 오류 수정: 피격 발광이 블룸과 겹쳐 적이 하얗게 날아가던 것(약한 붉은 기로 변경), 총구 섬광 조명에 1인칭 총이 하얗게 타던 것(세기 6→3.5), 1인칭 총의 발광판이 번져 뭉개지던 것(새 모델로 교체되며 해소).
- 검증: 1인칭 NORMAL 오토파일럿 승리(명중률 59%), 콘솔 오류 없음. 3인칭에서 걷기·달리기·뒷걸음 클립 전환과 재장전·사망·부활 확인. 오토파일럿은 눈 위치 기준으로 조준해서 3인칭에서는 명중률이 38%로 떨어진다(사람이 쏠 때의 조준점은 정확하다).
- 남은 점: 3인칭 재장전 때 왼손·총 경계에 잘린 조각이 가까이서 보인다. 1인칭 모델 파일이 3.0MB로 크다. 1인칭 재장전에서 탄창 교체 동작 자체는 보이지 않는다.

### 모션 수정

한 판 전체를 측정해 찾은 문제를 고쳤다(봇 1명·초당 클립 전환 1.5 → 1.0회, 한 바퀴 회전 0회).

- 봇이 멈출 때 달리기 → 조깅 → 걷기를 차례로 거치던 것: 걸음 종류를 '의도한 속도'(내려갈 때 천천히 따라감)로 고른다.
- 걸음을 바꿀 때 새 클립을 같은 보폭 위상에서 시작해 섞는 동안 발 위치가 맞는다(섞는 구간 미끄러짐 중앙값 0.5~0.65 m/s).
- 뒷걸음 → 돌아서 달리기처럼 다리가 180도 돌 때 조준 쪽을 지나가는 방향으로 돈다(반대로 돌면 상체가 한 바퀴 돈다).
- 걷기·조깅·뒷걸음 보폭을 줄여 골반이 덜 내려간다(최대 10cm → 4.5cm).
- 주인공 전용 달리기·질주·뒷걸음 클립(5.5 / 8.25 / 5.5 m/s). 봇 클립을 1.7배로 빨리 감던 것을 없앴다.
- 허리 비틀림을 골반과 가슴에 반씩 나누고, 주인공은 한계를 90도로 줄였다.
- 3인칭 재장전: 총을 가슴 앞에 둔 채 살짝 눕힌다. 팔을 몸통에서도 잘라 떼어 가슴과 붙은 면이 늘어나지 않게 했다. 사망 시 팔과 총이 몸 쪽으로 내려온다.
- 1인칭: 재장전이 도중에 끝나도(궁극기) 총이 튀지 않는다. 화면 귀퉁이에 보이던 상완을 잘라냈다.
- 남은 점: 발을 디딘 채 다리 방향을 돌릴 때의 미끄러짐(중앙값 2.5 m/s, 디딘 프레임의 약 27%)은 몸 중심으로 도는 구조라 그대로다.

### 탄환 이펙트 재작성

예전 탄환은 납작한 띠 한 장이었다. 내 총알처럼 시선과 거의 나란히 멀어지는 탄은 화면에서 길이가 점처럼 줄어드는데 폭은 그대로라, 폭 방향이 진행 방향과 직각인 '/' 모양 줄로 보였다.

- 새 탄환 = 둥근 머리(색 빛 + 흰 중심, 항상 카메라를 보는 원) + 진행 방향으로 늘어난 꼬리(`Fx.bolt`, `Fx.placeBolt`).
- 꼬리 폭은 화면에 보이는 길이(길이 × sin(진행 방향과 시선 사이 각))의 0.22배를 넘지 않는다. 시선과 나란하면 꼬리는 사라지고 머리만 남는다.
- 머리는 멀어져도 일정한 겉보기 크기 아래로 작아지지 않는다.
- 첫 프레임은 총구에 붙은 채로 그린 뒤 전진시킨다. 바로 전진시키면 화면에서 가장 길게 보이는 총구 앞 구간을 건너뛴다.
- 내 총알은 꼬리 9m·속도 150m/s, 적 총알은 꼬리 3m·140m/s. 꼬리 텍스처는 코드로 만든다(`makeTrailTexture`).
- 측정(임무 한 판, 폭 1px 이상인 탄 2,984개 표본): 폭이 길이보다 긴 경우 1개(카메라 바로 앞을 지나는 탄), 꼬리와 진행 방향의 어긋남 0도.
- 화면 오른쪽 아래에 빌드 시각(UTC)을 표시한다. 배포본이 새 빌드인지 확인하는 용도다.

### 옆걸음 (봇·주인공 공통)

예전에는 옆으로 움직이며 조준할 때 다리가 이동 방향을 보고 달리고 상체만 허리에서 약 90도 비틀었다. 옆걸음 전용 동작을 만들어 고쳤다.

- 클립: `strafeL/R`(2.8m/s), `strafeFastL/R`(5.5m/s). 몸은 정면을 본 채 발이 좌우로 디딘다. 두 발이 엇갈릴 때 뚫지 않게 한 발은 앞줄, 한 발은 뒷줄로 디딘다(`build_bot_rig.py`의 `STRAFE`).
- 걸음 방향 선택(`src/entities/GaitDir.ts`): 전진·뒷걸음·좌우 옆걸음 중 허리 비틀림(조준 방향 − 다리 방향)이 가장 작은 것을 고른다. 지금 걸음에는 17도쯤 여유를 줘 경계에서 왔다 갔다 하지 않는다. 좌↔우는 다리 방향이 같아 바뀌어도 다리가 돌지 않는다.
- 봇은 교전 중일 때만 네 방향을 쓰고, 아니면 가는 쪽을 보고 달린다. 주인공 3인칭은 항상 네 방향을 쓴다.
- 측정(봇, NORMAL 아레나 두 판, 옆으로 움직인 구간): 허리 비틀림 중앙값 87도 → 3도, 80도를 넘는 시간 69% → 1%, 일정하게 옆걸음할 때 발 미끄러짐 중앙값 0.06 m/s, 다리가 빠르게 도는 시간 21% → 13%, 한 바퀴 회전 0회.
- 대각선 이동: 다리는 조준 쪽을 본 채 두 걸음(예: 달리기 + 왼쪽 옆걸음)을 섞는다(`GaitDir.solveGaitBlend`). 두 클립을 같은 주기·같은 보폭 위상으로 맞춰 재생하면 접지한 발의 속도가 두 클립 속도의 가중합이 되므로, 가중치와 재생 배율을 풀어 발이 실제 이동 방향으로 디디게 한다. 다리가 조준 쪽으로 도는 중일 때의 차이도 같은 식으로 메운다.
- 대각선 섞기 후 측정(봇, NORMAL 아레나 한 판, 교전 중 이동 전체): 허리 비틀림 중앙값·90% 지점 0도(최대 42도), 다리가 빠르게 도는 시간 1%, 대각선 구간 발 미끄러짐 중앙값 0.24 m/s, 한 바퀴 회전 0회.
- 주인공 3인칭: 전 방향 허리 비틀림 0도, 대각선 발 미끄러짐 0.3 m/s 안팎. 걸음 종류는 '의도한 속도'로 고르고 속도가 0을 지나는 0.18초는 걷는 중으로 유지해, 좌우로 방향을 바꿀 때 클립이 한 번만 바뀐다(이전에는 느린 옆걸음·대기를 거쳤다).
- 오토파일럿은 3인칭에서 카메라 위치 기준으로 조준한다(조준선이 카메라에서 나간다). 아레나 명중률 3인칭 51%, 1인칭 58%(수정 전 3인칭 38~40%).

### 1인칭 재장전 리그 · 잘린 면 메우기

- 1인칭 모델(`fp_detail.glb`)이 한 덩어리 메시에서 리그로 바뀌었다: `gun`(총+오른팔), `fore.L`/`hand.L`(왼팔), `mag`(탄창 소품) 본과 `reload` 클립. `build_bot_rig.py ... fp`가 3인칭과 같은 재장전 시간표(`reload_timeline.py`)로 굽는다. 총을 기울이면 왼손이 아래로 빠졌다가 새 탄창을 들고 올라와 밀어 넣는다.
- 게임은 클립 시각을 재장전 진행도에 맞춘다(`Player.applyFpDetail`). 클립이 없으면 예전처럼 뷰모델을 기울이는 연출로 대신한다.
- 생성 메시는 겉에서 보이는 면만 있어서 팔에 가려진 가슴, 손에 가려진 총 표면이 원래 뚫려 있다. `bot_detail.swap_in`이 (1) 덩어리 표시를 이웃 다수결과 작은 섬 제거로 다듬고 (2) 열린 가장자리를 어두운 면(`detail_cap`)으로 메운다. 3인칭 재장전 때 보이던 조각과 가슴의 구멍이 없어졌다.
- 탄창은 상세 메시에서 분리되지 않아(총과 한 덩어리) 어두운 상자 소품을 쓴다. 평소에는 총의 탄창 안에 숨어 있다.

## 플레이테스트 (오토파일럿)

`src/dev/Autopilot.ts`는 사람처럼 플레이어를 조작한다(순찰 조준에서 임시 벡터가 겹쳐 항상 +z 벽을 보던 버그 수정)(반응시간·조준 오차·추적 속도·버스트·스트레이프·스킬 판단). 프로필: casual / average / good.
인게임 F8로 켜거나, 개발자 콘솔에서 시뮬레이션을 빠르게 돌려 밸런스 데이터를 뽑는다:

```js
// 콘솔: 난이도 버튼 클릭 → 시작 → 오토파일럿 → 60Hz 스텝을 직접 호출
document.querySelector('#difficulty [data-d="normal"]').click(); document.getElementById('btn-start').click();
game.setAutopilot('average'); for (let i = 0; i < 60 * 300; i++) game.step(1 / 60);
console.table(game.waveLog); console.log(game.player.stats);
```

2026-11-09 측정 (각 2회): EASY/casual 승리(사망 2) · NORMAL/average 웨이브 3~5 도달 · HARD/good 웨이브 2 전멸.
봇은 난이도별 공격 토큰(동시 사격 봇 수)과 피해 배율로 압박을 조절한다 (`src/data/difficulty.ts`).

## 배포 (GitHub Pages)

```bash
npm run deploy:pages
```

처음 실행 시 공개 저장소 `skyfall-arena`를 만들고 소스를 푸시한 뒤, `dist/`를 `gh-pages` 브랜치로 올리고 Pages 소스를 설정한다. 이후 실행은 빌드·재배포만 한다. Vite `base: './'`라 하위 경로(`/skyfall-arena/`)에서도 에셋 경로가 맞는다.
