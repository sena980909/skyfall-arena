# SKYFALL ARENA

웹 브라우저용 영웅 기반 하이퍼 FPS. 싱글 플레이 임무 '탈출': 관제동에 잠입한 요원이 증거를 빼내 기지를 빠져나간다(부활 없음).

> 아레나(웨이브 섬멸) 모드는 없앴다. 아래 기록 가운데 아레나·웨이브·목숨 셋·부활을 다룬 부분은 지나간 내용이다. 남쪽 구역은 이제 임무의 마지막 무대인 착륙장으로만 쓴다.
기획은 [GDD.md](GDD.md) 참고.

**플레이:** https://sena980909.github.io/skyfall-arena/  (GitHub Pages, 데스크톱 Chrome/Edge 권장)

## 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:5179 접속. **Pointer Lock(마우스 잠금)이 필요하므로 일반 Chrome/Edge 탭에서 실행**해야 마우스 시점이 동작한다 (임베디드 브라우저 패널에서는 시점 회전 불가).

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 (HMR) |
| `npm run typecheck` | 타입 체크 |
| `npm run build` | 타입 체크 + 프로덕션 빌드 (`dist/`) |

## 레이븐 키트 (돌격형 · 솔저 계열 구성)

| 키 | 스킬 | 수치 |
|---|---|---|
| 좌클릭 | 펄스 라이플 | 18 피해, 초당 9발, 30발, 헤드샷 ×2 |
| Shift | 달리기 | 이동 1.5배, 사격·로켓 사용 시 해제 |
| 우클릭 | 펄스 로켓 | 나선 3연 에너지탄, 직격 40 + 스플래시 80(반경 3m, 가장자리 50%), 쿨 6초 |
| E | 치유 필드 | 발밑 설치, 반경 4.5m, 초당 35 회복, 5초, 쿨 15초 |
| Q | 전술 조준 | 6초간 화면 안 적 자동 조준(몸통 판정), 발동 시 즉시 재장전 |

메커니즘 구성은 돌격형 영웅 아키타입을 따르되 이름·외형·사운드는 오리지널이다.

1인칭 뷰모델(`public/assets/models/fp_arms.glb`): 레이븐 컨셉(`assets/concept/raven_concept.png`)과 펄스 라이플 컨셉을 레퍼런스로 넣어 '주인공의 양팔이 라이플을 겨눈' 이미지(`assets/concept/fp_arms_concept.png`)를 만들고 image_to_3d로 변환한 단일 메시(30k tris, WebP 1K, 1.65MB). 왼손은 총열덮개를 아래에서 받치고 오른손 검지는 방아쇠, 전완은 팔꿈치까지 길어 절단면이 화면 밖에 있다. 전완 끝은 안으로 패인 컵 모양이라, 가장 낮은 정점 덩어리(왼팔 끝)와 총 아래 가장 뒤쪽 덩어리(오른팔 끝)를 찾아 관절 구로 막고 어깨(카메라 아래·뒤 양쪽) 방향으로 상완 원통을 이어 붙여(`ArmSleeves.ts`) 총을 들어도 빈 공간이 보이지 않고, 모델을 1.25m 길이(기존 0.92)로 36% 키우고 뷰모델을 올려 총구를 7° 들어 전완 장갑이 화면 하단에 크게 보이게 해 손·총이 공중에 뜬 인상을 없앴다. 정렬은 `alignGunUpright`(GunAlign.ts): 생성 모델의 +Y를 그대로 '위'로 두고 총 부분(모델 위쪽 절반)의 수평 주축으로 요만 -Z에 맞춘다. 메시 전체 PCA로 '위'를 추정하던 이전 방식은 팔 때문에 총이 10~30° 롤된 채 놓였다. 월드와 분리된 전용 FOV(`Player.VIEWMODEL_FOV`=56)로 2패스 렌더하고, 궤적·섬광·로켓 출발점은 두 FOV 차이를 보정한 총구 위치(`fxMuzzlePosition`)를 쓴다. 걸음 8자 흔들림, 옆걸음 기울임, 착지 반동, 숨쉬기, 반동 모션에 더해 질주 시 아래·안쪽 캐리 자세로 블렌드. 재장전은 총을 들어 올리지 않고 안쪽으로 굴리며 몸쪽으로 당기는 모션이다(뷰모델 피벗이 카메라 근처라 총구를 들면 카메라 앞 전완 절단면이 화면으로 올라온다).

탄환·섬광 VFX: 탄환 광선은 십자 평면 대신 매 프레임 카메라를 향해 축 회전하는 한 장의 리본으로, 꼬리가 총구에서 시작해 앞으로 자라며 총구 근처에서 페이드인(총구 바로 앞에서 세로 막대처럼 보이던 문제 제거). 섬광·탄환 텍스처는 힉스필드(gpt-image)로 재생성한 뒤 `tools/vfx-prep.mjs`(sharp)로 검정 배경 평탄화·중앙 크롭·가장자리 마스크를 적용해 가산 합성 시 스프라이트 사각 경계가 비치지 않게 했다.

사망 연출: 플레이어가 죽으면 카메라가 가속하며 맞은 쪽 반대로 기울어 바닥(눈높이 0.32m)까지 쓰러지고 살짝 튕긴 뒤, 1.4초에 걸쳐 처치자 쪽으로 고개가 돌아간다(`Player.updateDeathCam`). ELIMINATED 오버레이는 0.6초 뒤 얇은 붉은 비네트로 덮여 쓰러지는 장면이 보인다. 봇은 생성된 death 클립이 끝까지 서 있는 불량 클립이라, 피격 반대 방향으로 나무 넘어지듯 가속 회전해 눕고(0.55초) 0.9초 뒤 디졸브하는 절차적 넘어짐을 쓴다(`Bot.updateDeath`).

입력: 키 '방금 눌림'은 시뮬레이션 스텝이 소비한 뒤에만 지운다. 렌더 프레임마다 지우던 이전 방식은 스텝이 없는 프레임(고주사율 모니터)에서 점프·스킬 입력을 유실했다.

봇 교착 수정: (1) 경로 시작/목표 셀을 에이전트가 실제로 선 높이의 셀로 고른다(플랫폼 가장자리에 걸친 봇을 지면 셀로 잡으면 난간 너머로 가라는 경로가 나와 영원히 끼임). (2) 낙하 노드는 가장자리 너머로 0.6m 밀어내고, 실제로 내려간 뒤에만 도착 처리한다. (3) 플레이어가 교전 거리의 1.3배 밖이면 엄폐 대신 접근한다(멀리서 숨었다 쏘기 반복 교착 방지). (4) 경로 추종 중 2.2초 이상 완전히 멈추면 같은 높이의 근처 지점으로 우회.

봇 애니메이션 보정: 생성된 shoot/aim 클립은 왼손이 총을 잡지 않고 옆으로 뻗어 있고, aim 클립은 재생 중 상체가 130° 이상 돌아간다. 정지 사격·조준 대기에는 shoot 클립만 쓰고, 왼팔에 2본 IK(`Bot.solveLeftArmIK`)를 걸어 왼손이 항상 총열덮개(홀더 −Z 0.3m)를 잡게 했다. 1인칭 로켓 반동은 총구를 들어 올리는 대신 뒤로 밀어 전완 절단면이 보이지 않게 했다.

캐릭터 덩치 보정: 생성된 레이븐 모델은 컨셉·1인칭 팔보다 견장과 전완 장갑이 작게 나와, 어깨 본 1.35배(상완 역스케일로 팔 길이 유지)·전완 두께 1.3배(손 역스케일)를 매 프레임 적용한다(`Bot.applyArmorBulk`). 모델 재생성 없이 실루엣을 컨셉에 맞춘다.

봇 이동 애니메이션(문워크·머리 숙임 수정): 원인은 걷기 클립이 없어서 (1) 교전 중 옆걸음에 웅크린 사이드스텝 클립(머리 61° 숙임, 머리 높이 1.15m)을 이동 시간의 76% 동안 썼고 (2) 발 접지 속도가 0.26~0.89m/s인 클립을 2.6~4.7m/s 이동에 재생해 발이 미끄러졌기 때문이다. 수정: 다리(그룹)는 항상 실제 이동 방향을 보고, 교전 중 상체는 척추 3본 비틀림으로 조준 방향을 본다(`Bot.applyTorsoTwist`). 조준 반대로 물러날 때는 다리를 이동 반대쪽으로 돌리고 뒷걸음 클립을 쓴다(110°/80° 히스테리시스). 힉스필드로 걷기(Quick_Walk)·뒷걸음(Walk_Backward_with_Gun) 클립을 추가 생성했고, 재생 속도 = 이동 속도 / 클립의 발 접지 속도(`CLIP_SPEED`: 달리기 5.6, 걷기 1.55, 뒷걸음 1.43m/s, 브라우저에서 발 본으로 실측). 루트가 전진하는 클립은 로드 시 Hips 수평 이동분을 제거한다(`stripRootMotion`). 총은 교전 시 손이 아니라 목 기준 견착 위치에 고정하고 양팔 IK로 손을 총에 붙여, 달리기 클립의 팔 휘두름에 총이 끌려다니지 않는다. 웅크린 strafe 클립과 상체가 돌아가는 aim 클립은 더 이상 쓰지 않아 삭제했다.

봇 상체 빙글빙글 회전 수정: 척추 비틀림·팔 IK는 본 회전에 '덧붙이는' 방식인데, 믹서가 가중치 0인 순간 등 일부 프레임에 본 회전을 덮어쓰지 않아 덧붙인 회전이 누적됐다(배포본 실측: 봇 23기 중 18기가 1초 안에 상체 360° 이상 회전, 다리 대비 누적 8826°). 수정: (1) 매 프레임 믹서 갱신 전에 클립 원본 회전으로 복원하고 갱신 후 다시 저장(`Bot.updateMixer`), (2) 클립 가중치를 직접 관리해 합이 항상 1(`updateAnimWeights`, 기본 fadeIn/fadeOut은 빠른 전환 시 합이 1 미만이 되어 바인드 포즈가 섞임), (3) 상체 요를 월드 기준으로 따로 두고 각속도 제한으로 조준을 따라가며 비틀림은 연속값으로 갱신, (4) 이동/정지·전진/뒷걸음·클립 전환에 최소 유지 시간. 수정 후 같은 측정에서 360° 회전 0기, 누적 최대 145°.

### Blender 에셋 파이프라인 (v2, B0~B1 완료)

1인칭 팔+라이플은 이제 Blender에서 Python으로 직접 모델링·리깅·애니메이션한 리그(`public/assets/models/fp_rig.glb`, 17.3k tris, 본 39개, 0.95MB)를 쓴다. 이미지→3D 덩어리 메시(`fp_arms.glb`)는 새 리그가 없을 때만 내려받는 폴백이다.

- 소스: `tools/blender/lib_build.py`(프리미티브·베벨·리지드 스키닝 도구), `fp_rifle.py`(도면 픽셀 좌표로 만든 펄스 라이플), `build_fp_rig.py`(팔·손가락, 2본 IK 해석해로 포즈 계산, idle·reload 클립 베이크, GLB 내보내기). 결과 `.blend`는 `assets_src/fp_rig.blend`.
- 리그 공간 = 카메라 공간(원점이 눈, 정면 -Z)이라 뷰모델 원점에 그대로 붙는다. 방향 추정·롤 보정·절단면 메우기가 필요 없다.
- 팔은 어깨 뒤까지 모델링되어 어떤 화면비에서도 잘린 단면이 보이지 않는다. 손가락은 관절 3개씩 본이 있어 손잡이·총열덮개·탄창을 실제로 쥔다.
- 재장전 클립(총을 기울여 탄창을 빼고 새 탄창을 꽂음)은 무기의 재장전 진행도에 클립 시간을 직접 맞춰 재생한다(`Player.updateFpRig`).
- 다시 만들기: `blender -b --factory-startup --python tools/blender/build_fp_rig.py -- <프로젝트 절대경로>` (미리보기 렌더만: 끝에 `preview_only`).
- 참고 도면은 힉스필드로 생성(`assets_src/reference/`).

### Blender 에셋 파이프라인 B2: 적 봇 리그

적 봇도 Blender에서 직접 만든 리그(`public/assets/models/bot_rig.glb`, 10.9k tris, 본 11개, 클립 5개, 0.91MB)를 쓴다. 새 리그가 있으면 이전 에셋(raven.glb, 라이브러리 클립, pulse_rifle.glb)은 내려받지 않는다.

- 소스: `tools/blender/build_bot_rig.py`(몸·다리 모델링, 보행 생성, 굽기), `arm_lib.py`(팔·손 공용 모듈). 결과 `.blend`는 `assets_src/bot_rig.blend`.
- 본 구조: hips → torso → (head, armsgun → muzzle), 다리 6본. 팔과 라이플은 조준 자세 그대로 armsgun 본 하나에 묶여 있어 손이 총에서 떨어질 수 없다. 게임은 torso를 돌려 상체를 조준 방향으로 틀고(`applyTorsoTwist`), armsgun을 어깨 축으로 돌려 상하 조준과 로우레디를 만든다(`applyAimPitch`). 게임 쪽 IK·총 부착·장갑 확대 코드는 새 리그에서 쓰지 않는다.
- 이동 클립(walk 1.6 / jog 2.8 / run 4.7 / back 3.2 m/s)은 제자리 클립이고, 접지한 발이 정확히 그 속도로 뒤로 움직이도록 다리를 IK로 계산해 구웠다. 게임은 속도에 가장 가까운 클립을 골라 재생 속도 = 이동 속도 / 클립 속도로 맞춘다.
- 옆걸음 방향을 뒤집을 때는 다리를 180° 돌리지 않고 앞걸음/뒷걸음만 바꾼다.
- 실측(NORMAL 오토파일럿 한 판, 봇 23기): 접지한 발의 미끄러짐 중앙값 run 0.00 / jog 0.02 / back 0.06 / walk 0.22 m/s, 1초 안에 상체가 360° 넘게 돈 봇 0기.
- 재질 이름으로 팀 색을 입힌다: `bot_armor`·`armor_blue` = 팀 색(일반 주황, 보스 빨강), `bot_visor` = 바이저, `*glow*` = 발광.

### Blender 에셋 파이프라인 B3: 맵 모듈 키트

맵 외형도 Blender에서 만든 모듈 키트(`public/assets/models/map_kit.glb`, 모듈 14종, 7.4k tris, 0.49MB)로 바꿨다. 소스는 `tools/blender/build_map_kit.py`, 결과 `.blend`는 `assets_src/map_kit.blend`.

- 모듈: 컨테이너 4색, 크레이트 2종, 엄폐 방벽, 중앙 플랫폼(상판·기둥·난간·계단), 외벽 구간, 배경 타워, 벽 위 조명.
- 충돌 상자와 탄 판정용 메시는 그대로 두고 보이지 않게만 한 뒤(`GreyboxMap.applyKit`), 모듈을 상자 크기·방향에 맞춰 얹는다. three.js 레이캐스트는 visible을 보지 않으므로 판정·봇 시야·길찾기는 바뀌지 않는다.

- 배경 타워 13개와 벽 위 조명은 경기장 밖·벽 위에 있어 충돌과 판정이 없다.

### 디테일 텍스처 (힉스필드 생성 → 맵·봇·1인칭 리그)

단색이던 Blender 모델 세 종에 힉스필드로 만든 타일형 디테일 텍스처를 입혔다.

- 원본: `assets_src/textures_raw/`(패널 2종, 슈트 육각 직조, 벗겨진 도장). 게임용: `public/assets/textures/detail_{panel,suit,worn}.jpg`.
- 후처리 `node tools/tex-prep.mjs <원본.png> <결과.jpg> [크기] [평균 밝기] [대비]`: 회색조로 바꾸고 평균 밝기를 맞춘다. 텍스처는 색이 아니라 명암만 담고, 게임에서 재질 색·정점 색 위에 곱해진다. 그래서 팀 색 변경과 피격 점멸이 그대로 동작한다.
- UV: Blender 빌드에서 상자 투영 UV를 넣는다(`lib_build.box_uv`, 1칸 = 1인칭 리그 0.22m, 봇 0.45m, 맵 2.5m). 텍스처는 거울 반복이라 이음새가 없다.
- 적용: `Assets.applyDetailTextures`가 재질 이름으로 고른다. 맵 도장(`kit_paint`)은 벗겨진 도장, 슈트·장갑은 육각 직조, 나머지 장갑·총기는 패널. 발광·바이저 재질은 제외. 같은 텍스처를 bumpMap으로도 써서 패널 선에 음영이 생긴다.
- 검은 재질(총 몸통·총열, 봇 관절)은 어두운 선을 곱해도 보이지 않는다. 그래서 명암을 뒤집은 `detail_panel_dark.jpg`(`tex-prep.mjs ... invert`)를 쓰고 재질 색을 3.8배 밝혀, 바탕 밝기는 그대로 두고 패널 선만 밝게 띄운다(`DARK_MATERIAL`, `DARK_GAIN`).
- 2차 조정: 대비를 패널 1.0→1.5, 도장 1.6→2.2, 슈트 1.0→1.5로, bumpScale을 0.9/0.8/0.4로 올렸다.
- 검증: 타입 검사 통과, 재질 13종에 텍스처 적용 확인, NORMAL 오토파일럿 한 판 승리(명중률 54%, 이전 55%), 콘솔 오류 없음.

### 효과음 4차: 재장전 단계별 동기화 + 발소리·착지 클립

- 재장전음을 세 단계로 나눠 1인칭 재장전 애니메이션의 동작 시점에 낸다(`Player.RELOAD_CUES`, `Sfx.reloadStage`). 탄창 분리 0.14초, 새 탄창 삽입 0.93초, 왼손 복귀 1.15초. 이전에는 시작할 때 한 번에 재생해 삽입음이 0.62초에 나서 화면(0.93초)과 어긋났다.
- 힉스필드(Mirelo SFX)로 발소리·착지·탄창 분리·삽입음을 새로 만들었다. 18개를 만들어 WebAudio 분석(피크, 소리 구간, 잡음 바닥)으로 8개를 골랐다. 나머지 10개는 거의 무음이거나 저음 웅웅거림이라 버렸다. 원본은 `assets_src/sfx_raw/`.
- 발소리 4종, 착지 2종은 재생할 때마다 직전과 다른 것을 무작위로 고른다. 플레이어 발소리, 봇 발소리(3D 위치), 착지에 쓴다.
- `manifest.json` 항목이 파일명 외에 `{ file, from, to }`와 배열을 받는다. 생성 클립은 1초 안에 소리가 뒤쪽에 있거나 여러 번 나서, 필요한 구간만 잘라 쓰고 구간 안의 첫 소리 지점까지 앞 무음을 걷어낸다(`AudioBank.cut`).
- 합성음은 그대로 바탕으로 두고 클립이 있을 때 0.6배로 줄여 겹친다. 장전 완료음(3단계)은 생성 결과가 쓸 만하지 않아 합성음만 쓴다.
- 검증: 오토파일럿 한 판에서 재장전 18회의 단계별 재생 시점이 클립 시각 0.13 / 0.92 / 1.13~1.15초, 발소리 클립 1,118회, 착지 3회 재생, 콘솔 오류 없음. 소리의 질감은 사람 귀로 확인이 필요하다(자동 검증은 파형 분석까지).

### 화면 연출: 후처리·조명·탄흔

- 후처리(`src/render/PostFx.ts`): 월드와 1인칭 뷰모델을 각자의 렌더 타깃에 그려 합친 뒤 블룸 → 톤매핑·sRGB → 화면 보정 순으로 처리한다. 화면 보정은 비네트, 분할 톤(밝은 곳 따뜻하게·어두운 곳 차갑게), 약한 대비 상승, 필름 그레인, 가장자리 색수차.
- 뷰모델을 별도 타깃에 그리는 이유: 멀티샘플 타깃에 지우지 않고 두 번 그리면 첫 번째 그림(월드)이 보존된다는 보장이 없다. 뷰모델 타깃은 투명 배경으로 지우고 셰이더에서 월드 위에 덮는다. 안티에일리어싱은 타깃의 4배 멀티샘플을 쓴다.
- 피격 반응: 맞은 만큼 색수차와 붉은 가장자리가 순간적으로 강해진다. 체력이 35% 아래로 내려가면 채도가 빠지고 가장자리가 붉게 뛴다.
- 조명: 해를 낮고 따뜻하게(세기 1.8→2.7), 하늘빛을 약하게(0.9→0.62) 바꿔 볕과 그늘의 대비를 키웠다. 노출 1.05→1.22, 안개 시작 거리 120→60m.
- 탄흔(`Fx.decal`): 탄이 맵에 맞으면 그을음 자국이 남고 달아오른 점이 0.7초 동안 식는다. 최대 48개를 돌려쓰고 9초 뒤 사라진다. `hitscan` 결과에 표면 법선(`normal`)을 추가했다.
- F7로 후처리를 켜고 끈다. 플레이 첫 240프레임의 평균이 40fps에 못 미치면 자동으로 끄고 알림을 띄운다.
- 측정(내장 브라우저, RTX 4060, 966×846): 후처리 켬 158fps, 끔 164fps. NORMAL 오토파일럿 한 판 승리(명중률 60%), 콘솔 오류 없음. 저사양 그래픽 기기에서의 프레임은 측정하지 못했다.

### 적 봇 상세 모델 (힉스필드 이미지→3D + 기존 리그)

적 봇의 겉모습을 힉스필드로 만든 상세 메시로 바꿨다. 본·애니메이션·게임 로직은 직접 만든 리그 그대로다.

1. 현재 절차 모델을 정면·좌측·후면 직교 뷰로 렌더한다(`tools/blender/render_bot_views.py` → `assets_src/reference/bot_view_*.png`).
2. 그 렌더를 자세·비율 기준으로 넣어 상세 디자인 이미지를 만든다(GPT Image 2.6, 3장, `assets_src/higgs/bot_detail_{front,left,back}.png`). 자세가 리그와 같아야 하므로 새 자세를 그리게 하지 않고 기존 모델을 '다시 디자인'하게 한다.
3. 세 장을 Tripo H3.1 멀티뷰 이미지→3D에 넣어 GLB를 받는다(`assets_src/higgs/bot_detail.glb`, 19k tris, 텍스처·PBR 포함, 9 크레딧).
4. `tools/blender/bot_detail.py`가 상세 메시를 절차 메시에 정렬하고(90도 단위 회전 4가지 중 최적 + 이동·배율 보정, 평균 오차 1.3cm), 각 정점에서 가장 가까운 절차 메시 면의 본을 물려받게 한 뒤 관절 경계의 가중치를 이웃과 섞는다. 바이저 면은 `bot_visor` 재질로 나눠 게임이 색·발광을 바꿀 수 있게 한다.
5. `build_bot_rig.py`는 `assets_src/higgs/bot_detail.glb`가 있으면 자동으로 상세 메시를 쓴다. 인자에 `no_detail`을 주면 절차 모델로 빌드한다.

- 결과: `bot_rig.glb` 1.40MB(텍스처 1024 JPEG 3장), 삼각형 10.9k → 19.2k, 본 11개·클립 5개는 동일.
- 게임: 자체 텍스처가 있는 재질에는 디테일 텍스처를 덮지 않는다. 보스는 텍스처 위에 붉은 색을 곱한다.
- 검증: NORMAL 오토파일럿 한 판 승리(명중률 63%), 콘솔 오류 없음. 상체 회전 측정은 배포본(이전 모델)과 같은 범위였다(1초 안에 한 바퀴 넘게 도는 봇이 판마다 0~3/23, 모델 교체와 무관한 기존 수치).

### 주인공 상세 모델: 3인칭 몸 + 1인칭 팔·총

주인공은 적과 같은 상세 모델의 파란색 판이다. 3인칭 몸과 1인칭 팔·총을 같은 디자인·같은 총 쥐는 자세에서 만들었다.

- **3인칭 몸** (`player_rig.glb`, `build_bot_rig.py ... player`): 적 봇 리그에 팔 관절(상완·전완·손)과 총·탄창 본, 재장전 클립을 더했다. 색은 텍스처의 따뜻한 색을 파란색·청록색으로 바꿔 만든다(`bot_detail.recolor_blue`). 생성 메시는 손·총·가슴이 한 표면이라 재장전처럼 손이 총에서 떨어지면 그 사이가 길게 늘어난다. 그래서 따로 움직여야 하는 덩어리(왼팔 아래쪽 / 오른팔+총 / 몸)의 경계에서 메시를 잘라 떼어 놓는다(`swap_in(part_of, joined)`).
- **재장전 시간표 공유** (`tools/blender/reload_timeline.py`): 기울임, 탄창 분리, 새 탄창, 밀어 넣기, 왼손 복귀의 구간을 한곳에 두고 3인칭 클립·1인칭 연출·효과음 시점이 같이 쓴다. 3인칭에서는 왼손이 왼쪽 골반 앞 주머니에서 새 탄창을 꺼내 온다.
- **3인칭 시점** (V): 오른쪽 어깨 너머 카메라(옆 0.5m·위 0.15m·뒤 2.8m, 벽에 막히면 그 앞까지). 조준 광선은 카메라에서 조준점으로 나가되 몸 깊이에서 시작해 카메라와 몸 사이의 물체는 맞히지 않는다. 다리는 이동 방향, 상체는 조준 방향을 향하고 팔·총은 조준 피치만큼 돈다(`src/entities/PlayerBody.ts`). 사망하면 몸이 뒤로 쓰러진다.
- **1인칭 팔·총** (`fp_detail.glb`, `build_bot_rig.py ... fp`): 몸이 총을 든 자세에서 팔·총만 따로 상세 모델로 만들었다. 절차 모델의 팔·총을 정면·좌·후면으로 렌더(`... fpref`)해 자세 기준으로 쓰고, 같은 디자인의 파란색 확대 이미지 3장 → Tripo 멀티뷰(38k tris, 텍스처 2048)로 만든 뒤 절차 팔·총에 정렬한다(평균 오차 6mm). 눈이 원점이라 뷰모델에 그대로 붙이고 조준 높이까지 올려 놓는다.
- 1인칭 모델은 팔·총이 한 덩어리라 본 애니메이션이 없다. 재장전은 같은 시간표로 총을 기울여 화면 아래로 내렸다 올리고, 탄창이 걸리는 순간 살짝 튄다.
- 생성 모델의 거칠기 맵은 거의 거울 수준(평균 0.17)이라 가까이서 젖은 크롬처럼 보인다. 1인칭에서는 금속성 0.3·거칠기 0.55 고정에 노멀 맵만 쓴다.
- 전신 모델에서 팔·총만 잘라 1인칭에 쓰는 방법은 해상도가 모자라 뭉개져서 버렸다. Tripo의 텍스처 '상세' 옵션은 색 텍스처가 회색으로 비어 나와 표준 옵션으로 다시 만들었다.
- 화면 오류 수정: 피격 발광이 블룸과 겹쳐 적이 하얗게 날아가던 것(약한 붉은 기로 변경), 총구 섬광 조명에 1인칭 총이 하얗게 타던 것(세기 6→3.5), 1인칭 총의 발광판이 번져 뭉개지던 것(새 모델로 교체되며 해소).
- 검증: 1인칭 NORMAL 오토파일럿 승리(명중률 59%), 콘솔 오류 없음. 3인칭에서 걷기·달리기·뒷걸음 클립 전환과 재장전·사망·부활 확인. 오토파일럿은 눈 위치 기준으로 조준해서 3인칭에서는 명중률이 38%로 떨어진다(사람이 쏠 때의 조준점은 정확하다).
- 남은 점: 3인칭 재장전 때 왼손·총 경계에 잘린 조각이 가까이서 보인다. 1인칭 모델 파일이 3.0MB로 크다. 1인칭 재장전에서 탄창 교체 동작 자체는 보이지 않는다.

### 모션 수정

한 판 전체를 측정해 찾은 문제를 고쳤다(봇 1명·초당 클립 전환 1.5 → 1.0회, 한 바퀴 회전 0회).

- 봇이 멈출 때 달리기 → 조깅 → 걷기를 차례로 거치던 것: 걸음 종류를 '의도한 속도'(내려갈 때 천천히 따라감)로 고른다.
- 걸음을 바꿀 때 새 클립을 같은 보폭 위상에서 시작해 섞는 동안 발 위치가 맞는다(섞는 구간 미끄러짐 중앙값 0.5~0.65 m/s).
- 뒷걸음 → 돌아서 달리기처럼 다리가 180도 돌 때 조준 쪽을 지나가는 방향으로 돈다(반대로 돌면 상체가 한 바퀴 돈다).
- 걷기·조깅·뒷걸음 보폭을 줄여 골반이 덜 내려간다(최대 10cm → 4.5cm).
- 주인공 전용 달리기·질주·뒷걸음 클립(5.5 / 8.25 / 5.5 m/s). 봇 클립을 1.7배로 빨리 감던 것을 없앴다.
- 허리 비틀림을 골반과 가슴에 반씩 나누고, 주인공은 한계를 90도로 줄였다.
- 3인칭 재장전: 총을 가슴 앞에 둔 채 살짝 눕힌다. 팔을 몸통에서도 잘라 떼어 가슴과 붙은 면이 늘어나지 않게 했다. 사망 시 팔과 총이 몸 쪽으로 내려온다.
- 1인칭: 재장전이 도중에 끝나도(궁극기) 총이 튀지 않는다. 화면 귀퉁이에 보이던 상완을 잘라냈다.
- 남은 점: 발을 디딘 채 다리 방향을 돌릴 때의 미끄러짐(중앙값 2.5 m/s, 디딘 프레임의 약 27%)은 몸 중심으로 도는 구조라 그대로다.

### 탄환 이펙트 재작성

예전 탄환은 납작한 띠 한 장이었다. 내 총알처럼 시선과 거의 나란히 멀어지는 탄은 화면에서 길이가 점처럼 줄어드는데 폭은 그대로라, 폭 방향이 진행 방향과 직각인 '/' 모양 줄로 보였다.

- 새 탄환 = 둥근 머리(색 빛 + 흰 중심, 항상 카메라를 보는 원) + 진행 방향으로 늘어난 꼬리(`Fx.bolt`, `Fx.placeBolt`).
- 꼬리 폭은 화면에 보이는 길이(길이 × sin(진행 방향과 시선 사이 각))의 0.22배를 넘지 않는다. 시선과 나란하면 꼬리는 사라지고 머리만 남는다.
- 머리는 멀어져도 일정한 겉보기 크기 아래로 작아지지 않는다.
- 첫 프레임은 총구에 붙은 채로 그린 뒤 전진시킨다. 바로 전진시키면 화면에서 가장 길게 보이는 총구 앞 구간을 건너뛴다.
- 내 총알은 꼬리 9m·속도 150m/s, 적 총알은 꼬리 3m·140m/s. 꼬리 텍스처는 코드로 만든다(`makeTrailTexture`).
- 측정(임무 한 판, 폭 1px 이상인 탄 2,984개 표본): 폭이 길이보다 긴 경우 1개(카메라 바로 앞을 지나는 탄), 꼬리와 진행 방향의 어긋남 0도.
- 화면 오른쪽 아래에 빌드 시각(UTC)을 표시한다. 배포본이 새 빌드인지 확인하는 용도다.

### 옆걸음 (봇·주인공 공통)

예전에는 옆으로 움직이며 조준할 때 다리가 이동 방향을 보고 달리고 상체만 허리에서 약 90도 비틀었다. 옆걸음 전용 동작을 만들어 고쳤다.

- 클립: `strafeL/R`(2.8m/s), `strafeFastL/R`(5.5m/s). 몸은 정면을 본 채 발이 좌우로 디딘다. 두 발이 엇갈릴 때 뚫지 않게 한 발은 앞줄, 한 발은 뒷줄로 디딘다(`build_bot_rig.py`의 `STRAFE`).
- 걸음 방향 선택(`src/entities/GaitDir.ts`): 전진·뒷걸음·좌우 옆걸음 중 허리 비틀림(조준 방향 − 다리 방향)이 가장 작은 것을 고른다. 지금 걸음에는 17도쯤 여유를 줘 경계에서 왔다 갔다 하지 않는다. 좌↔우는 다리 방향이 같아 바뀌어도 다리가 돌지 않는다.
- 봇은 교전 중일 때만 네 방향을 쓰고, 아니면 가는 쪽을 보고 달린다. 주인공 3인칭은 항상 네 방향을 쓴다.
- 측정(봇, NORMAL 아레나 두 판, 옆으로 움직인 구간): 허리 비틀림 중앙값 87도 → 3도, 80도를 넘는 시간 69% → 1%, 일정하게 옆걸음할 때 발 미끄러짐 중앙값 0.06 m/s, 다리가 빠르게 도는 시간 21% → 13%, 한 바퀴 회전 0회.
- 대각선 이동: 다리는 조준 쪽을 본 채 두 걸음(예: 달리기 + 왼쪽 옆걸음)을 섞는다(`GaitDir.solveGaitBlend`). 두 클립을 같은 주기·같은 보폭 위상으로 맞춰 재생하면 접지한 발의 속도가 두 클립 속도의 가중합이 되므로, 가중치와 재생 배율을 풀어 발이 실제 이동 방향으로 디디게 한다. 다리가 조준 쪽으로 도는 중일 때의 차이도 같은 식으로 메운다.
- 대각선 섞기 후 측정(봇, NORMAL 아레나 한 판, 교전 중 이동 전체): 허리 비틀림 중앙값·90% 지점 0도(최대 42도), 다리가 빠르게 도는 시간 1%, 대각선 구간 발 미끄러짐 중앙값 0.24 m/s, 한 바퀴 회전 0회.
- 주인공 3인칭: 전 방향 허리 비틀림 0도, 대각선 발 미끄러짐 0.3 m/s 안팎. 걸음 종류는 '의도한 속도'로 고르고 속도가 0을 지나는 0.18초는 걷는 중으로 유지해, 좌우로 방향을 바꿀 때 클립이 한 번만 바뀐다(이전에는 느린 옆걸음·대기를 거쳤다).
- 오토파일럿은 3인칭에서 카메라 위치 기준으로 조준한다(조준선이 카메라에서 나간다). 아레나 명중률 3인칭 51%, 1인칭 58%(수정 전 3인칭 38~40%).

### 1인칭 재장전 리그 · 잘린 면 메우기

- 1인칭 모델(`fp_detail.glb`)이 한 덩어리 메시에서 리그로 바뀌었다: `gun`(총+오른팔), `fore.L`/`hand.L`(왼팔), `mag`(탄창 소품) 본과 `reload` 클립. `build_bot_rig.py ... fp`가 3인칭과 같은 재장전 시간표(`reload_timeline.py`)로 굽는다. 총을 기울이면 왼손이 아래로 빠졌다가 새 탄창을 들고 올라와 밀어 넣는다.
- 게임은 클립 시각을 재장전 진행도에 맞춘다(`Player.applyFpDetail`). 클립이 없으면 예전처럼 뷰모델을 기울이는 연출로 대신한다.
- 생성 메시는 겉에서 보이는 면만 있어서 팔에 가려진 가슴, 손에 가려진 총 표면이 원래 뚫려 있다. `bot_detail.swap_in`이 (1) 덩어리 표시를 이웃 다수결과 작은 섬 제거로 다듬고 (2) 열린 가장자리를 어두운 면(`detail_cap`)으로 메운다. 3인칭 재장전 때 보이던 조각과 가슴의 구멍이 없어졌다.
- 탄창은 상세 메시에서 분리되지 않아(총과 한 덩어리) 어두운 상자 소품을 쓴다. 평소에는 총의 탄창 안에 숨어 있다. (1인칭 탄창은 나중에 생성 메시로 바꿨다: '1인칭 재장전 자세 다시 잡기' 절)
- **이음매 붙이기(`weld=True`)**: glTF는 UV 이음매마다 정점을 따로 두어서, 불러온 메시는 UV 조각 수백 개가 서로 떨어진 상태다. 그대로 두면 덩어리 사이를 자를 변을 찾지 못하고(자른 변 0개), 구멍 메우기가 조각마다 어두운 면을 하나씩 씌운다 (1인칭 128장, 3인칭 89장) — 총과 가슴을 덮던 검은 삼각 조각, 재장전 때 총 옆에 떠 있던 파편이 이것이었다. 먼저 정점을 붙인 뒤 자르고 메우면 메운 면은 실제로 뚫린 곳(1인칭 10장, 3인칭 7장)에만 남는다.
- 1인칭 재장전 자세는 총을 조금 더 들어 올려, 새 탄창이 들어가는 모습이 화면 안에 보이게 했다.

### 임무용 맵 확장: 관문 · 화물 통로 · 북쪽 야드

- 맵이 남쪽 아레나(80×60m)에서 북쪽으로 이어진다: 관문(8m) → 화물 통로(18×40m) → 북쪽 야드(60×50m). 전체 길이 약 150m(`GreyboxMap.buildNorth`).
- 임무 흐름: 아레나의 중계기 2기 복구 → 관문 개방 → 통로 돌파(들어서면 매복) → 야드의 세 번째 중계기 복구 → 야드 중앙 신호기로 탈출선 호출 → 60초 방어 → 추적자 처치 → 55초 안에 통로를 되돌아가 남쪽 착륙장으로 탈출. 방어 이후 체크포인트는 야드다.
- 관문은 닫혀 있는 동안 충돌·탄 판정에 들어가고, 열리면 빠진다(`GreyboxMap.setGate`). 여닫을 때 길찾기 격자를 다시 만든다(약 25ms, 4.9만 칸). 아레나 모드에서는 관문이 닫힌 채라 북쪽 구역은 도달 불가로 빠지고 봇도 넘어가지 않는다.
- 적은 관문이 열리면 야드 지점에서도 나오고, 플레이어에게서 22~75m 떨어진 지점만 쓴다.
- 그림자 범위(해)는 플레이어를 4m 단위로 따라간다. 맵이 길어져 고정 범위로는 다 덮지 못한다.
- 검증: NORMAL 오토파일럿이 임무를 2회 완주(3분 42초, 3분 56초, 사망 0). 내장 브라우저(RTX 4060) 164fps로 확장 전과 같다. 아레나 모드 한 판 승리.

오토파일럿 한 판을 돌려 잰 값으로 전후를 비교했다 (임무 모드, 60Hz).

- **걸음 고르기**: 조준 방향이 아니라 다리가 지금 실제로 향한 방향을 기준으로 걸음을 고르고, 남는 각은 옆 걸음을 섞어 메운다(`GaitDir.solveGaitBlend`).

- **재장전 손**: 탄창에서 손을 떼는 구간과 총열 덮개로 돌아오는 구간을 하나로 합쳤다. 따로 두면 손이 주머니 쪽으로 내려갔다가 다시 올라온다(`tools/blender/reload_timeline.py`).

### 제자리 돌기 (봇·주인공 공통)

서 있을 때 다리를 조준 쪽으로 계속 돌리면 디딘 두 발이 턴테이블처럼 바닥에서 돈다. 이제 다리는 그대로 두고 상체만 조준을 따라가다가,
비틀림이 커지면(봇 40°, 주인공 34°) 또는 비틀린 채 잠시 서 있으면 발을 한 쪽씩 떼어 한 걸음에 돈다.

- **클립** `turnL`/`turnR` (`build_bot_rig.py`): 90° 돌기(봇은 0.4초, 주인공은 0.3초에 재생). 게임이 몸(그룹)을 돌리는 만큼 클립이 발에서 그 회전을 되돌려, 디딘 발이 바닥에 붙어 있다.
  도는 쪽 발을 먼저 옮기고 반대쪽 발이 따라온다. 처음과 끝 자세는 `idle`과 같다.
- **작은 각**은 `idle`과 섞어 쓴다(가중치 = 각/90°). 90°보다 크면 여러 걸음으로 나눠 돈다.
- 몸이 도는 곡선은 게임(`GaitDir.turnYawProgress`)과 Blender(`turn_progress`)가 같은 식을 쓴다. 다르면 디딘 발이 미끄러진다.
- 돌기 클립은 가중치를 바로 준다(천천히 올리면 디딘 발이 다리 회전을 따라가지 못한다). 도는 중에 움직이기 시작하면 그 자세로 멈춘 채 걸음 클립과 섞이며 빠진다.

| 서 있는 동안 디딘 발이 미끄러진 거리 | 전 | 후 |
|---|---|---|
| 주인공(3인칭, 정해 둔 회전 순서 14초) | 초당 0.30m | 초당 0.035m |
| 봇(임무 한 판) | 초당 0.175m | 초당 0.05m |

남은 것: 주인공이 시점을 90° 넘게 한 번에 돌리면 허리 비틀림 한계 때문에 다리가 그 프레임에 끌려 돈다.

### 관제동: 첫 실내 구역

야드 북쪽 벽에 출입구를 내고 그 너머에 실내 구역(48×46m, 천장 4.7m)을 붙였다. 지금까지는 전부 야외였다.

```
          ┌──────────── 관제실 (중계기 3 · 큰 화면) ────────────┐
          │   문(서)                                   문(동)   │
          ├────────┬───────── 서버실 ─────────┬────────┤
          │ 서쪽 방 ├─ 옆문    (랙 4대)    옆문 ─┤ 동쪽 방 │
          ├── 문 ──┴────────── 문 ───────────┴── 문 ──┤
          │                    로비                    │
          └────────────────── 출입구 ──────────────────┘
                              야드
```

- **구조**: 로비에서 서쪽 방·서버실·동쪽 방으로 갈라지고, 관제실로는 서쪽·동쪽 방에서만 들어간다. 서버실은 두 방을 잇는 옆문만 있다 → 어느 쪽으로 돌지 고르게 되고, 관제실은 문이 둘이라 양쪽을 다 봐야 한다.
- **임무**: 세 번째 중계기가 야드에서 관제실로 옮겨 갔다. 관제동에 들어서면 방 안에서 기다리던 적 셋(중장병 하나 포함)이 나오고, 중계기에 손대면 매복이 온다. 복구한 뒤의 흐름은 아래 '임무 단계 추가' 절을 본다.
- **적 등장 지점** 6곳을 실내에 추가했다. 야드에서 방어할 때 관제동 문으로도 적이 나온다.
- **조명**: 천장이 햇빛을 막고, 천장 조명판(발광)과 점광원 셋(로비는 따뜻한 색, 서버실·관제실은 청록)이 비춘다. 점광원은 모든 재질의 셰이더 비용을 올려서 모바일에서는 넣지 않는다.
- **길찾기**는 높이필드라 2층을 만들 수 없다. 천장은 걸을 수 있는 높이 한계(4.6m)보다 높게 두어 지면 계산에서 빠지게 했다.
- **그리기 비용**: 관제동은 아레나에서는 야드 벽에 가려 보이지 않으므로 그동안 통째로 그리지 않는다(문 자리에는 어두운 판을 세워 둔다).

| 시점 | 드로콜 전 | 후 |
|---|---|---|
| 아레나 시작 지점에서 북쪽 | 453 | 465 |
| 야드 남쪽 끝에서 북쪽 | 228 | 381 |
| 야드 북쪽 끝에서 남쪽 | 508 | 509 |
| 관제실 안쪽에서 남쪽(가장 나쁜 경우) | — | 666 |

오토파일럿 임무 9판: 승리 8, 패배 1(보스·탈출 단계에서 3번 사망). 한 판 길이는 213~288초(전에는 200~230초), 실내에서 보내는 시간은 32~83초. 플레이어·봇이 끼어 멈춘 곳은 없었다.

### 임무 단계 추가: 자료 전송(거점 유지) · 전원 셀 운반

지금까지 임무는 'F를 누르고 있기'와 '시간 버티기' 두 가지 규칙뿐이었다. 관제동 안팎에 규칙이 다른 단계 둘을 넣었다.

지금 흐름: 아레나 중계기 2기 → 관문 → 통로 → 야드 → 관제동 관제실의 중계기 → **서버실에서 자료 전송** → **전원 셀 2개를 신호기로 운반** → 신호기로 탈출선 호출 → 60초 방어 → 추적자 처치 → 55초 안에 남쪽 착륙장으로 탈출.

- **자료 전송(거점 유지)**: 서버실 안에 서 있으면 진행도가 오른다(방해가 없으면 35초). 살아 있는 적이 서버실 안에 하나라도 있으면 멈춘다. 진행도는 줄지 않는다.
  - 8초마다 적 둘이 관제동의 다른 방에서 나온다(동시에 넷까지). 플레이어 눈에 보이지 않는 지점을 먼저 고른다.
  - 다음 적이 올 때까지의 시간은 플레이어가 서버실 안에 있는 동안에만 흐른다. 죽어서 돌아오는 사이에 적이 쌓이지 않는다.
  - 기존 적은 10~20m 거리를 지키므로 방에 들어오지 않는다. 그래서 **돌입병**을 넣었다(`BotOptions.rush`): 3~6m까지 파고들고 체력은 일반병의 70%다. 무리마다 하나씩 섞인다.
  - 표시: 벽을 따라 도는 바닥 띠와 문턱 셋의 굵은 띠가 청록(전송 중)에서 빨강(적이 안에 있음)으로 바뀐다. 화면 가운데 진행 막대도 같은 상태를 알린다.
- **전원 셀 운반**: 셀은 서버실과 화물 통로에 하나씩 있고, 가까이 가면 집는다(한 번에 하나). 야드 신호기 옆에 가면 꽂힌다.
  - 들고 있는 동안은 달릴 수 없다(`Player.carrying`). 쏘는 것과 스킬은 그대로다.
  - 죽으면 마지막으로 디딘 자리에 떨어지고, 다시 가서 집는다.
  - 서버실 셀을 집으면 로비에 경비병 둘, 그 셀을 들고 야드로 나서면 차단조 셋, 통로 셀을 집으면 추격조 셋이 나온다.
  - 3인칭에서는 셀이 등에 보인다(`torso` 뼈에 붙인다). 1인칭에서는 목표 아래 문구로만 알린다.
- 체크포인트: 전송을 끝내면 서버실, 셀을 하나 꽂으면 야드.
- 오토파일럿: 전송 단계에서는 서버실 가운데로 가서 보이는 적과 싸우고, 운반 단계에서는 가까운 셀 → 신호기 순서로 간다(`Mission.goal`).

| 오토파일럿 임무 10판 (NORMAL, average) | 전(관제동만) | 후 |
|---|---|---|
| 승리 | 9판 중 8 | 10판 중 10 |
| 한 판 길이 | 213~288초 | 307~378초 |
| 자료 전송 단계 | — | 47~81초 (적이 방 안에 있어 멈춘 시간 1~24초) |
| 운반 단계 | — | 46~89초 |
| 사망 | — | 10판에 8번 (전송 2, 운반 2, 추적자 4) |

전송 무리의 세기는 세 가지로 재서 골랐다. 돌입병 체력 100%에 적이 계속 쌓이게 두면 7판에 9번을 전송 단계에서 죽었고(패배 2), 동시에 셋·9초 간격으로 줄이면 전송이 멈추는 시간이 거의 0초여서 규칙이 드러나지 않았다.

목표였던 7~8분에는 못 미친다(오토파일럿으로 5분 7초~6분 18초). 오토파일럿은 길을 헤매지 않고 늘 달리므로 사람은 더 걸리겠지만 재지는 못했다.

### 적 종류: 돌입병 · 저격병

적이 전부 같은 병사라 어느 적을 먼저 처리할지 고를 일이 없었다. 같은 리그와 애니메이션을 그대로 쓰고 색·크기·무기·교전 거리만 다른 종류 둘을 넣었다. 수치는 `src/data/enemies.ts` 한곳에 있다.

| 종류 | 색 | 체력 | 교전 거리 | 무기 | 대처 |
|---|---|---|---|---|---|
| 돌격병 | 주황 | 100% | 10~20m | 펄스 라이플(끊어 쏘기) | 기준 |
| 돌입병 | 초록, 크기 90% | 70% | 3~6m, 이동 속도 115% | 근접 기관단총(14m 밖에서는 30% 피해) | 다가오기 전에 먼저 처리 |
| 저격병 | 자홍, 긴 총열 | 80% | 18~45m, 조준 중에는 멈춰 선다 | 조준선 1.2초 → 0.25초 굳힘 → 한 발(75 × 난이도 배율) | 조준선이 보이면 옆으로 움직이거나 엄폐 |

- **색**: 상세 메시는 텍스처에 색이 들어 있어 색을 곱해서는 주황이 다른 색이 되지 않는다(어두워질 뿐이다). 셰이더에서 색 채널을 바꿔 끼운다(`render/HueSwap`). 회색인 총과 관절은 그대로 남는다. 종류별 셰이더는 로딩 때 미리 컴파일한다(살아 있을 때·사라질 때 것 모두).
- **저격병의 한 발**: 조준선(총구에서 실제로 맞을 지점까지)이 플레이어를 따라오다가, 쏘기 0.25초 전에 굳는다. 앞을 내다보고 쏘지 않으므로 옆으로 움직이면 빗나가고, 서 있거나 저격병 쪽으로 곧장 걸으면 맞는다. 공격 토큰(동시에 쏘는 적 수 제한)과는 따로다.
- **등장**: 임무에서는 두 번째 중계기 매복·서버실 무리·통로 셀 추격조에 돌입병, 통로 매복과 셀을 들고 나서는 야드에 저격병이 하나씩 나온다. 방어 단계는 무리마다 돌입병 → 저격병(한 번에 하나만) → 중장병이 돌아가며 섞인다. 아레나는 2웨이브부터 돌입병, 3웨이브부터 저격병이 섞인다(`data/waves.ts`).

저격병 한 명과 22m 거리에서 30초 (NORMAL, 7발):

| 플레이어 | 맞은 횟수 |
|---|---|
| 서 있음 | 5 |
| 저격병 쪽으로 앞뒤로 걸음 | 5 |
| 좌우로 걸음(1.2초마다 방향 전환) | 0 |
| 좌우로 걸음(2.5초마다 방향 전환) | 1 |

오토파일럿 (NORMAL, average): 임무 8판 모두 승리(331~395초, 사망 7번: 돌입병 4, 돌격병 2, 중장병 1), 아레나 4판 모두 승리(147~174초, 판마다 1~2번 사망). 오토파일럿은 교전 중 늘 좌우로 움직여서 저격병에게는 판마다 0~2발만 맞았다. 가만히 서서 쏘는 사람에게는 더 아플 것이다(재지 못했다).

### 1인칭 재장전 자세 다시 잡기

재장전하는 동안 총이 화면 한가운데를 가렸다. 새 탄창이 들어가는 모습이 보이게 하려고 총을 들어 올렸던 것이 원인이다. 게다가 0.3~0.7초 사이에는 화면 안에서 아무것도 움직이지 않았다(왼손과 탄창이 화면 밖).

- 총을 오른쪽 아래에 둔 채 더 눕혔다(40° → 66°). 탄창 구멍이 왼쪽 아래를 향해서 빈 탄창이 빠지고 새 탄창이 들어오는 모습이 화면 아래쪽에 보인다.
- 총이 굳어 있지 않게 작은 움직임 셋을 넣었다: 빈 탄창을 털어 내는 손목 꺾기, 탄창을 가지러 간 동안 천천히 내려앉기, 밀어 넣을 때 들썩임.
- 시간표(`reload_timeline.py`)와 효과음 시점은 그대로다. 3인칭 리그는 건드리지 않았다.

| 재장전 1.4초 동안 (뷰모델만 그려서 잰 값) | 전 | 후 |
|---|---|---|
| 조준점이 총에 가린 시간 (16:9 · 4:3 · 19.5:9 모두) | 1.05초 | 0초 |
| 화면 가운데 영역(가로 30% × 세로 40%)이 가린 비율, 평균 (16:9) | 41.8% | 12.6% |
| 같은 영역, 가장 많이 가린 순간 (16:9) | 50.7% | 14.4% |

평소 자세에서는 같은 영역의 8.6%가 가린다.

**탄창 모델**: 재장전 때 보이는 탄창이 어두운 상자에 빛나는 줄 하나라서, 텍스처가 입혀진 총 옆에서 따로 놀았다. 총과 같은 방식으로 다시 만들었다.

1. 총·팔 그림(`assets_src/higgs/fp_arms_left.png`)을 참고로 주고 같은 양식의 탄창 한 개를 그린다(GPT Image 2.6, `mag_concept.png`).
2. 그 그림을 Tripo H3.1 이미지→3D에 넣어 GLB를 받는다(`assets_src/higgs/mag_detail.glb`, 5.1k tris, 9 크레딧).
3. `bot_detail.import_prop`이 탄창 자리 상자(3.6 × 10.5 × 10cm)에 맞춰 넣고 `mag` 본에 통째로 붙인다. 표면은 총과 같게 금속·거칠기 지도를 빼고 상수로 둔다. 텍스처는 512로 줄인다.

1인칭 모델은 3.04MB → 3.43MB가 됐다. 3인칭 리그의 탄창은 화면에서 몇 픽셀이라 상자 그대로다.

### 헤드샷 표시

머리 판정과 피해 2배(`headshotMult`)는 처음부터 있었지만 표시가 약해서 있는 줄 알기 어려웠다: 명중 표시가 흰색에서 노란색으로, 피해 숫자가 18px에서 22px로 바뀌는 정도였다.

- 명중 표시: 빨갛고 굵게, 2.1배로 튀어나왔다 줄어든다. 헤드샷 처치도 주황(처치) 대신 빨강으로 뜬다.
- 피해 숫자: 빨강 30px, 튀어나오는 효과.
- 맞은 자리에서 붉은 불꽃, 헤드샷 처치 때 조준점 아래 `HEADSHOT` 문구.
- 시작 화면 조작 안내에 "머리를 맞히면 피해 2배"를 넣었다.

확인 (근거리, 6초 연사): 머리를 조준하면 돌격병 27발·돌입병 28발·저격병 15발이 36 피해, 몸통을 조준하면 40발 모두 18 피해. 머리 판정(반지름 22cm 구)과 보이는 머리의 어긋남은 아레나 한 판 동안 중앙값 4.6cm, 90% 지점 8cm였다.

### 맵 소품을 생성 모델로 (시험: 4종)

상자·컨테이너·방벽·임무 단말의 겉모습을 힉스필드로 만든 모델로 바꿨다. 충돌 상자, 길찾기, 임무 로직은 그대로다. 벽·바닥·계단은 직접 만든 모듈 그대로 둔다(생성 모델은 치수가 정확하지 않고 텍스처가 반복되지 않아 이어 붙이는 면에는 맞지 않는다).

1. 탄창 그림을 양식 참고로 주고 소품마다 그림 한 장을 그린다(GPT Image 2.6, `assets_src/higgs/prop_*.png`).
2. Tripo H3.1 이미지→3D로 GLB를 받는다(`prop_*.glb`).
3. `build_map_kit.py`의 `generated()`가 모듈 상자에 축마다 맞춰 넣는다(`bot_detail.import_static`). 재질은 모듈당 하나, 금속·거칠기 지도는 빼고 텍스처는 JPEG로 싣는다. 파일이 없거나 인자에 `no_gen`을 주면 예전 절차 모델로 빌드한다.

| 모듈 | 삼각형 | 텍스처 | 비고 |
|---|---|---|---|
| 상자 `kit_crate` | 2,600 | 512 | 높은 상자는 둘을 쌓아 만든다(위 것은 90° 돌림) |
| 컨테이너 `kit_container_a~d` | 1,800 | 1024 | 메시·텍스처는 하나. 절반은 게임이 색 채널을 바꿔 파란색으로 보인다(`HueSwap` bgr) |
| 방벽 `kit_barrier` | 1,500 | 1024 | 생성 모델이 짧고 두꺼워서 길이 쪽으로 2배 늘려 맞췄다 |
| 단말 `kit_console` | 2,631 | 512 | 중계기·신호기·전송 단말. 상태 고리와 등은 따로 붙인다(게임이 색을 바꾼다) |

겪은 것:

- 상자를 면 수 2,000으로 뽑았더니 메시가 깨져 나왔다(가시처럼 뻗은 삼각형). 5,000으로 다시 뽑고 Blender에서 줄였다.
- 줄이는 데 한계가 있다: 상자를 1,200까지 줄이면 옆면 텍스처가 일그러진다. 2,600에서는 가까이서 봐도 멀쩡하다. 평평한 면을 먼저 합치는 방식은 효과가 없었다(생성 메시는 겉이 고르지 않아 6%만 줄었다).
- 방벽 텍스처는 512로는 6m 길이에 흐려서 1024로 올렸다.

같은 절차(새 페이지, 같은 위치·방향 여섯 곳, 봇 없음)로 잰 값:

| 위치 | 드로콜 전 → 후 | 삼각형 전 → 후 |
|---|---|---|
| 아레나 시작 지점에서 북쪽 | 508 → 424 | 15.1만 → 29.1만 |
| 아레나 가운데에서 남쪽 | 327 → 277 | 12.0만 → 20.0만 |
| 통로 입구에서 북쪽 | 525 → 438 | 14.6만 → 30.7만 |
| 야드 남쪽 끝에서 북쪽 | 466 → 387 | 13.8만 → 28.3만 |
| 야드 북쪽 끝에서 남쪽 | 558 → 469 | 15.6만 → 30.4만 |
| 관제동 로비에서 북쪽 | 338 → 286 | 11.8만 → 20.7만 |

드로콜은 15~17% 줄었다(소품마다 재질이 둘에서 하나로). 삼각형은 두 배 가까이 늘었다(그림자 패스 포함). 데스크톱(RTX 4060)에서 프레임 시간은 늘지 않았다. 폰에서는 재지 못했다. `map_kit.glb`는 0.64MB → 1.69MB.

비용: 그림 4장 2 크레딧 + 3D 변환 5번 45 크레딧(상자 한 번 다시) = 47 크레딧.

**오토파일럿 모서리 끼임**: 이 작업 중 오토파일럿이 방벽 끝에서 수백 초씩 멈추는 판이 나왔다(16판 중 3판). 겉모습과는 무관하고 원래 있던 문제다: 경로 지점에 70cm 안으로만 가면 다음 지점으로 넘어가서, 모서리를 다 돌기 전에 방벽 끝을 향해 곧장 밀었다. 다시 경로를 잡아도 같은 자리에서 시작하므로 풀리지 않았고, 스텝마다 조금씩 떨려서 끼임 감지도 걸리지 않았다. 이제 다음 지점까지 곧게 갈 수 있을 때만 넘어가고(`NavGrid.clearLine`), 끼임은 0.8초 동안 30cm 안에 머무는지로 본다. 고친 뒤 임무 12판 모두 승리, 끼임 0번.

### 높낮이가 있는 배치

소품을 좋은 모델로 바꿔도 장면이 납작했다: 야드와 통로는 평평한 바닥에 높이가 비슷한 소품이 하나씩 흩어져 있었다(가장 높은 것이 2.5m 컨테이너).

- **하역장** (야드 서쪽, 8.5 × 12m, 높이 1.35m): 신호기 쪽과 남쪽에 계단. 위에 난간·방벽·상자가 있고, 서쪽 힐팩을 이 위로 옮겼다. 신호기를 내려다보는 자리다.
- **2단 컨테이너**: 야드 셋(기존 둘 위 + 동쪽 벽 앞 새 한 쌍), 통로 하나, 아레나 모서리 둘. 위 것은 조금 어긋나게 놓았다.
- **갠트리 크레인** (야드 가운데): 다리 넷(7m), 보 셋, 신호기 옆 위에 매달린 컨테이너. 보와 매달린 컨테이너는 4.5m 위라 이동과 길찾기에는 영향이 없고 탄만 막는다.
- **상자 무더기**: 높은 상자 옆에 낮은 상자(밟고 올라가는 단), 컨테이너 위에 얹은 상자, 통로의 높은 상자.
- 계단은 어느 방향·높이로든 놓을 수 있게 했다(`GreyboxMap.addStairs`, 키트 태그 `stairs`). 전에는 아레나 중앙 단의 동·서 계단만 자리가 고정돼 있었다.

확인: 하역장 위와 그 위의 힐팩까지 길이 이어지고, 적 등장 지점 17곳과 힐팩 11곳 모두 도달 가능. 계단 둘 다 걸어서 올라간다(높이 1.35m 도달).

| 위치 | 드로콜 (소품 교체 후 → 배치 후) | 삼각형 |
|---|---|---|
| 아레나 시작 지점에서 북쪽 | 424 → 465 | 29.1만 → 32.9만 |
| 통로 입구에서 북쪽 | 438 → 478 | 30.7만 → 34.2만 |
| 야드 남쪽 끝에서 북쪽 | 387 → 427 | 28.3만 → 30.7만 |
| 야드 북쪽 끝에서 남쪽 | 469 → 502 | 30.4만 → 33.4만 |

오토파일럿 임무 12판: 모두 승리(303~401초), 끼임 0번. 그 전 12판에서는 탈출 단계에서 시간 초과로 진 판이 하나 있었다: 맞으면서 힐팩 사이를 오가다 55초를 다 썼다. 오토파일럿이 탈출 중에는 힐팩을 찾아다니지 않게 했다(체력 50 아래에서 15m 안의 것만).

### 접지 그림자 · 빛 대비

소품이 바닥에 얹어 놓은 것처럼 보였다: 해 그림자가 닿지 않는 쪽 바닥은 소품 밑까지 똑같이 밝았고, 하늘빛이 강해서 그늘진 면과 볕 드는 면의 차이도 작았다.

- **접지 그림자** (`GreyboxMap.buildContactShadows`): 바닥에 닿는 상자 122개(소품·벽·기둥·계단)의 발자국 둘레에, 바깥으로 옅어지는 어두운 띠를 바닥에 깐다. 넓고 옅은 띠(1.3m)와 좁고 진한 띠(0.42m) 두 겹이고 농도는 정점 알파다. 화면 공간 AO가 아니라 미리 만든 메시라 비용은 드로콜 둘(야외·관제동)과 삼각형 5,900개뿐이고 모바일에서도 그대로 나온다.
- **빛 대비**: 해 2.7 → 3.3, 하늘빛(반구광) 0.62 → 0.42, 환경맵 세기 1 → 0.7, 노출 1.22 → 1.2. 그늘이 깊어져 소품의 볕 드는 면과 그늘진 면이 갈린다.
- **실내는 그대로**: 관제동 안에는 해가 들지 않아 하늘빛을 줄이면 그만큼 어두워진다. 카메라가 관제동에 들어가면 하늘빛과 환경맵 세기를 예전 값으로 되돌린다(0.2초에 걸쳐).

화면 밝기 (같은 시점, 0~255 휘도 평균과 어두운 화소(64 미만) 비율):

| 시점 | 평균 전 → 후 | 어두운 화소 전 → 후 |
|---|---|---|
| 야드 북쪽 끝 | 100.4 → 95.3 | 27% → 33% |
| 야드 상자 가까이 | 81.0 → 74.0 | 40% → 52% |
| 아레나 시작 지점 | 110.5 → 106.4 | 25% → 32% |
| 통로 입구 | 106.9 → 100.6 | 29% → 39% |
| 관제동 로비 | 62.9 → 60.8 | 68% → 71% |
| 관제동 서버실 | 67.0 → 66.1 | 61% → 61% |

밝은 화소(128 이상) 비율은 어느 시점에서도 1~2%p 안에서만 바뀌었다: 밝은 곳은 그대로 두고 그늘만 깊어졌다. 드로콜은 시점마다 4 늘었다(아레나 시작 지점 465 → 469).

측정할 때 주의: 그림자 범위는 `frame()`이 플레이어를 따라 옮긴다. 스텝과 렌더만 직접 돌리는 검증에서는 순간이동 직후 한 프레임을 기다려야 한다(안 기다리면 50m 넘게 옮긴 자리에는 그림자가 없다).

### 상자 모양 소품은 겉그림만 쓴다 (컨테이너 · 상자)

직접 해 보면 컨테이너가 울퉁불퉁했다: 골판이 구겨진 것처럼 들쭉날쭉하고 테두리가 녹은 듯 휘었다. 원인은 둘이다.

- 이미지→3D 메시는 수천 면으로는 평평한 면과 곧은 모서리를 만들지 못한다. 원본(2,532면)부터 골판 깊이가 6~18cm로 고르지 않다.
- 거기에 내가 면 수를 줄이면서(1,800면) 더 찌그러뜨렸다. 줄이기 전으로 되돌려도 휜 테두리와 고르지 않은 골은 남았다.

그래서 상자 모양 소품은 생성 메시의 **모양을 버리고 겉그림만** 쓴다(`bot_detail.project_box`): 생성 메시를 여섯 방향에서 직교 투영으로 찍어 한 장에 모으고, 깨끗한 상자(면마다 테두리 + 안으로 들어간 판)에 입힌다. 골판·문·볼트는 그림으로 남고 윤곽은 곧다.

| | 삼각형 전 → 후 | 텍스처 |
|---|---|---|
| 컨테이너 | 1,800 → 108 | 2048 × 1024 한 장 |
| 상자 | 2,600 → 108 (높은 상자 216) | 1024 × 1024 한 장 |

방벽과 단말은 상자 모양이 아니라 생성 메시 그대로 둔다(방벽은 줄였던 면 수를 원본 2,148로 되돌렸다).

같은 여섯 시점에서 삼각형이 절반 가까이로 줄었다: 아레나 시작 지점 33.7만 → 17.4만, 통로 35.4만 → 18.3만, 야드 북쪽 끝 34.5만 → 18.3만. 드로콜은 그대로다. `map_kit.glb` 1.69MB → 1.30MB.

교훈: 사진처럼 찍은 화면 몇 장만 보고 넘어갔다. 생성 소품은 비스듬한 각도에서 가까이 붙어 윤곽선을 봐야 한다.

### 앉기

**C**를 누르고 있는 동안 앉는다(터치는 '앉기' 버튼, 누를 때마다 켜고 끈다). Ctrl은 쓰지 않는다: 브라우저에서 Ctrl+W가 탭을 닫는다.

| | 서 있을 때 | 앉았을 때 |
|---|---|---|
| 충돌 높이 | 1.8m | 1.25m |
| 눈높이 | 1.6m | 1.05m |
| 머리 판정 중심 / 몸통 판정 높이 | 1.62m / 1.5m | 1.07m / 1.05m |
| 이동 속도 | 5.5m/s (질주 8.25) | 2.75m/s, 질주 불가 |

- **엄폐**: 방벽(1.1m)과 상자(1.0m) 뒤에 붙어 앉으면 눈높이가 그 아래라 적에게 보이지 않는다. 적의 시야·조준은 플레이어의 실제 머리·가슴 높이를 쓴다(`Player.headHeight`, `chestHeight`). 전에는 고정값(1.5m, 1.0m)이었다.
- **일어서기**: 머리 위가 막혀 있으면 일어서지 않는다(`CharacterController.fits`).
- **3인칭 몸**: 앉은 자세 `crouch`(한쪽 무릎을 내린 자세)와 앉아 걷기 넷(`crouchWalk`·`crouchBack`·`crouchStrafeL/R`, 2.75m/s)을 `build_bot_rig.py`에서 만들었다(주인공 리그만). 골반을 0.48m 낮추고 허리를 숙이며, 대각선은 서서 걸을 때처럼 두 클립을 섞는다.
- 앉은 채로는 발을 떼는 제자리 돌기를 쓰지 않는다(돌기 클립이 서 있는 자세다). 다리가 조준을 천천히 따라 돌아서 발이 조금 미끄러진다.

확인:

| 항목 | 결과 |
|---|---|
| 방벽 뒤 1m에 앉음, 적 7.6m (5초) | 본 프레임 0 / 300, 피해 0 |
| 같은 자리에 서 있음 (4초) | 본 프레임 240 / 240, 피해 26 |
| 상자 뒤에 앉음 / 서 있음 | 0 / 300, 피해 0 · 240 / 240, 피해 38 |
| 방벽에서 4m 떨어져 앉음 | 보이지만(300 / 300) 5초 동안 피해 0: 가슴을 노린 탄은 방벽에 막힌다 |
| 머리 위 1.5m에 판을 두고 C를 뗌 | 앉은 채 유지, 판을 치우면 일어섬 |
| 디딘 발 미끄러짐(앉아 걷기 넷·대각선) | 평균 초속 0.20~0.37m (서서 달리기 0.28, 옆걸음 0.31과 같은 수준) |

오토파일럿은 앉지 않는다. 임무 4판·아레나 2판 모두 승리(끼임 0).

### 임무 '탈출' 다시 짜기: 실내에서 시작 · 부활 없음 · 이야기

전에는 남쪽 착륙장에서 시작해 관제동까지 들어갔다가 되돌아 나왔다. 이제 **관제동 안에서 시작해 밖으로 빠져나간다.** 아래가 지금 흐름이고, 앞 절들의 임무 순서 설명은 옛 것이다.

**이야기**: 공중 화물 기지 스카이독을 장악한 아르고스 보안군이 화물 항로를 조작해 물자를 빼돌리고 있다. 정찰 요원 레이븐은 증거(항로 기록)를 찾아 관제동에 잠입했지만 경보가 울렸다. 본부 '등대'의 안내로 기록을 전송하고, 탈출선 '제비'를 불러 착륙장에서 빠져나간다. (이름·설정은 모두 이 게임의 것이다.)

| 순서 | 곳 | 할 일 |
|---|---|---|
| 1 | 관제실(시작) | 보안 단말로 봉쇄 해제(F 유지). 손대면 순찰하던 경비병 셋이 몰려온다 |
| 2 | 서버실 | 항로 기록 전송(거점 유지) |
| 3 | 서버실 → 야드, 화물 통로 → 야드 | 전원 셀 2개를 신호기로 운반 |
| 4 | 야드 | 신호기로 제비 호출 → 60초 방어 → 추적자 처치 |
| 5 | 통로 → 관문 → 착륙장 | 추적자의 인증키로 남쪽 관문이 열린다. 유도등 2기 점등(F 유지) |
| 6 | 착륙장 | 45초 안에 탈출 지점 도달 |

- **부활 없음**: 임무는 목숨 하나다. 쓰러지면 그 자리에서 임무 실패.
- **적을 줄였다**: 한 판에 나오는 적이 약 50 → 35. 시작 경비병은 새로 나오지 않고 순찰하다 몰려오고, 전송 무리는 10초마다 1~2명(동시에 셋까지, 중장병 없음), 방어 무리는 12초마다(동시에 셋까지), 셀·추적자·유도등 매복은 한 명씩 뺐다.
- **무전 자막**(`Hud.comm`): 화면 아래에 화자와 한 줄이 차례로 뜬다. 이야기와 다음 할 일을 여기로 전한다(등대·제비·레이븐). 시작 화면에 배경 설명 두 줄, 결과 화면에 결말 한 줄.
- **길찾기**: 관문이 닫혀 있는 동안은 시작 자리가 있는 쪽만 도달 가능 영역이 된다(`NavGrid`의 seed). 임무는 북쪽, 아레나는 남쪽.

오토파일럿 30판 (NORMAL, average, 목숨 하나): 승리 26판(87%), 이긴 판의 길이 227~261초. 진 4판은 운반·추적자·유도등 단계에서 한 번씩 쓰러졌다. 이긴 판 중 3분의 1은 체력이 30 아래까지 내려갔다. 사람이 하면 이보다 어려울 것이다(재지 못했다).

### 임무 '탈출'을 네 막으로: 조용한 도입, 무전으로 이어지는 이야기

전에는 시작하자마자 경비병 셋이 순찰을 돌았고, 첫 목표에 손대면 바로 싸움이 났다. 한 판이 오토파일럿으로 4분이었다. 이제 **처음 1분 남짓은 적이 없고**, 적은 '무슨 일이 일어난 뒤에' 나온다. 아래가 지금 흐름이다(앞 절들의 임무 순서는 옛 것).

| 막 | 곳 | 일어나는 일 |
|---|---|---|
| 1막 잠입 | 관제동 로비(시작, 닫힌 정문 안쪽) → 관제실 | 걸어 들어가며 무전을 듣는다. 보안 단말 접속(F) → 기록은 서버실에 있다 → 서버실 전송 단말에서 회선 열기(F) → 조용히 전송 |
| 2막 발각 | 서버실 → 관제실 | 전송 36%에서 경보(조명이 붉게 깜박인다). 6초 뒤 첫 경비병. 전송이 끝날 때까지 서버실 방어 → 봉쇄된 정문을 보안 단말에서 푼다(F, 경비병이 온다) → 정문이 열린다 |
| 3막 신호 | 북쪽 야드 | 야드는 비어 있다. 신호기까지 걸어가 보니 전원이 없다 → 전원 셀 2개(서쪽 하역장 위, 남쪽 화물 통로) 운반. 첫 셀을 들고 5초 뒤 저격병 → 제비 호출(F) → 70초 버티기(첫 무리는 10초 뒤) → 추적자 |
| 4막 탈출 | 화물 통로 → 남쪽 착륙장 | 추적자의 인증키로 남쪽 관문이 열린다. 통로에 들어서면 관문 너머의 저격병 → 유도등 2기(F) → 제비가 내려온다 → 45초 안에 탑승 |

- **무전은 시뮬레이션 시간으로 흐른다**(`Mission.say`): 줄마다 3.2~6.2초, 일시정지하면 대사도 멈춘다. 경고는 지금 나오는 줄을 끊고 먼저 나온다(`urgent`). 상황이 바뀌면 밀린 대사를 버린다(`cut`).
- **무전 구간**(`stage 'radio'`): 등대가 다음 일을 설명하는 동안은 다음 목표가 뜨지 않는다. 대사가 끝나야 넘어간다(네 군데: 보안 단말 접속 뒤, 전송 완료 뒤, 신호기 도착 뒤).
- **막 제목**: 막이 바뀔 때 화면 위에 4.5초 동안 뜬다(`Hud.chapter`).
- **관제동 정문**(`GreyboxMap.setDoor`): 두 짝이 벽 속으로 밀려 들어가며 열린다. 닫혀 있는 동안은 길찾기 격자가 관제동 안만 덮고, 적도 관제동 안에서만 나온다.
- **등장 지점**: 플레이어 눈에 보이지 않고 떨어진 곳을 먼저 고른다(`pickHidden`). 눈앞에서 불쑥 나타나지 않는다.
- **탈출선 '제비'**: 유도등을 다 켜면 남쪽 하늘에서 7초에 걸쳐 내려와 탈출 지점 위에 뜬다. 모델은 힉스필드 그림 → 이미지→3D(11,450삼각형, `kit_ship`), 맵 키트에 함께 들어 있다(`map_kit.glb` 1.30 → 1.97MB).
- 경보·문·무전 소리는 합성음이다(`SynthSfx.alarm / door / radio`).

오토파일럿 10판 (NORMAL, average, 목숨 하나): **10판 모두 승리, 316~354초**(전 227~261초). 첫 적이 나오는 때 61초(전 0초), 처음 맞는 때 63~90초. 한 판에 나오는 적 30~31(전 약 35). 오토파일럿은 처음부터 뛰어서 곧장 간다. 사람이 하면 더 길 것이다(재지 못했다). 이긴 판이 81% → 100%로 늘었다: 아래의 봇 움직임 변경으로 쉬워진 몫이 크다.

### 봇 움직임: 느리게, 서서히

봇은 바라는 속도가 그 프레임에 그대로 적용되어 출발·정지·방향 전환이 한 프레임에 끝났고, 교전 중에는 쉬지 않고 좌우로 오가며 1.2~2.2초마다 그 자리에서 방향을 뒤집었다.

- **가속·감속**(`Bot.drive`): 수평 속도가 바라는 속도를 시간 상수 0.16초로 따라간다.
- **서서 쏘기**: 옆걸음(1.0~2.0초)과 서서 쏘기(돌격병 1.0~2.2초, 돌입병 0.3~0.7초, 저격병 1.2~2.4초)를 번갈아 한다.
- **속도**: 돌격병 5.5 → 4.4 m/s, 돌입병 6.3 → 5.5, 저격병 4.95 → 3.85(플레이어 걷기 5.5, 달리기 8.25). 순찰은 걷는다(3.3 → 1.76 m/s). 몸 돌리는 속도 400 → 315°/s.

야드에서 25초 동안 잰 값(플레이어가 보이는 채로 교전):

| | 전 | 후 |
|---|---|---|
| 가속도 최대 (돌격병) | 357~395 m/s² | 41 m/s² |
| 진행 방향이 한 프레임에 90° 넘게 뒤집힌 횟수 | 16~32 | 0 |
| 움직인 시간의 비율 (돌격병) | 100% | 53~56% |
| 다가올 때 속도 (돌격병 / 돌입병) | 4.7 / 5.4 m/s | 3.7 / 4.7 m/s |

### 실내를 생성 모델로: 서버 랙 · 벽 · 제어대 · 정문 · 바닥 요철, 1인칭 총 다시 생성

**깜박임**: 경보가 울린 뒤 관제동 조명이 1.6초 주기로 끝없이 깜박였다(벽에 비친 빛이 싸우는 내내 출렁였다). 이제 처음 5초만 깜박이고(점점 약하게) 붉은 비상등으로 가만히 켜져 있다. 화면을 16x10칸으로 나눠 칸마다 밝기 변동 폭을 잰 값(서 있는 채로, 평균): 평소 0.41 → 경보 중 4.49(전에는 계속 이 값) → 5초 뒤 0.44. 관제실 큰 화면의 1픽셀 격자선은 2픽셀로 굵게 하고 이방성 필터를 켰다(움직일 때 자글거렸다). 필름 그레인은 0.022 → 0.012.

**벽 · 서버 랙 · 제어대 · 정문**: 벽은 Blender에서 상자 몇 개로 짠 모듈에 단색을 칠한 것이었고, 서버 랙·제어대·정문은 어두운 상자에 빛나는 띠만 붙어 있었다. 넷 다 컨테이너와 같은 길로 바꿨다: 그림(GPT Image 2.6) → 이미지→3D(Tripo H3.1) → 여섯 면을 직교 투영으로 찍어 깨끗한 상자(테두리 + 안으로 들어간 판)에 입힌다(`BD.project_box`). 생성 메시의 울퉁불퉁한 모양은 쓰지 않는다.

### 1인칭 총: 총만 따로 생성해 갈아 끼우기

고해상도로 다시 받은 팔+총 메시도 쏘는 사람 자리에서 보면 울퉁불퉁했다. 팔과 총을 한 덩어리로 만든 메시는 면의 대부분이 팔에 쓰이고, 참고 그림 세 장(앞·옆·뒤)에 총의 윗면과 뒤쪽이 거의 안 나와 그 부분이 뭉개진다. 화면에는 바로 그 윗면과 뒤쪽이 가장 크게 보인다.

- **총만 따로**: 총 하나만 그린 그림(뒤쪽 위에서 본 3/4 시점, 쏘는 사람이 보는 쪽)을 Tripo H3.1 이미지→3D에 `geometry_quality`·`texture_quality: detailed`, 150,000면으로 넣었다(`assets_src/higgs/rifle_rear34.png` → `rifle_detail.glb`). 판이 평평하고 모서리가 곧다.
- **갈아 끼우기**(`swap_in(strip=...)` + `BD.fit_prop`): 절차 리그에서 총 부품에 표시(정점 그룹 `GUNPART`)를 해 두고, 팔+총 메시에서 그 부품에 가장 가까운 면(29,401개)을 떼어 낸다. 새 총은 떼어 낸 면에 맞춰 놓는다(상자 → 크기·위치 → 강체 미세 맞춤, 평균 오차 3.2mm). 앞뒤가 거의 같은 오차로 맞아서, 가는 쪽 끝(총열)이 총구 본에 가깝도록 모양으로 가린다. 새 총은 `gun` 본 하나에 묶인다.
- **팔 끝**: 상완을 면 표시로 버리던 것을 평면으로 자르게 바꿨다(`plane_cuts`). 표시의 경계가 들쭉날쭉해서 팔꿈치 둘레에 찢어진 가시가 남아 있었다.
- 처음 받은 총은 어깨받침이 높아 화면 오른쪽 아래를 회색 판이 차지했다. 받침을 잘라 내면 잘린 면이 검은 판으로 보여서, 뒤가 낮고 평평한 총으로 그림을 고쳐 다시 받았다.
- 1인칭 메시 71,346 → 92,998삼각형(팔 33k + 총 55k + 탄창 5k), `fp_detail.glb` 4.9 → 6.7MB.
- 조준점 가림(화면 가운데 28x28픽셀): 대기·걷기·옆걸음·달리기·연사 3초·재장전·앉기·앉아 쏘기·점프 모두 0초. 처음 맞춘 자리에서는 2초 넘게 연사하면 조준경 모서리가 2~5% 들어와서 총을 1.2cm 내렸다.
- 3인칭 몸과 적이 든 총은 예전 모양 그대로다. 팔(전완·손)도 예전 생성 메시다.

### 1인칭 총을 설계도대로: 탄창이 달린 총, 탄창 본, 총구 위치

앞 절에서 갈아 끼운 총은 어깨받침을 없애려고 뒤쪽을 고쳐 그린 것이라 이 게임의 총 설계도(`assets_src/reference/rifle_ortho.png`)와 달랐다: 탄창이 없었고, 재장전 때는 예전 탄창 소품이 총과 따로 놀았다.

- **설계도를 참고로 다시 그렸다**: 설계도(왼쪽·위·앞·뒤)와 앞 절의 그림(재질·디테일)을 함께 넣고 같은 3/4 뒤쪽 시점으로 그린 뒤 이미지→3D(150,000면, 정밀)로 받았다. 손잡이 뒤·몸통 아래에 탄창이 있는 불펍 모양이다.
- **탄창은 총에서 잘라 낸다**(`fit_prop(split=('mag', 0.115, 0.275))`): 총 길이의 11.5~27.5%(뒤에서부터) 구간에서 몸통 아랫면보다 아래로 내려온 부분을 떼어 `mag` 본에 묶는다. 잘린 양쪽(몸통의 탄창 구멍, 탄창 윗면)은 어두운 판으로 막는다. 따로 만든 탄창 소품(`mag_detail.glb`)은 1인칭에서 더 쓰지 않는다.
- **본을 총에 맞춘다**: 탄창 본과 재장전 클립이 손을 뻗는 지점(`R.MAG_CENTER`, `R.MAG_BOTTOM`)을 실제 탄창 자리로(설계도 자리에서 5.5cm 앞), 총구 본을 실제 총열 끝으로(7.4cm 뒤, 2.4cm 위) 옮긴다. 섬광과 궤적이 총열 끝에서 나온다.
- 재장전 클립에서 탄창은 총에서 최대 42cm 떨어졌다가 제자리(0cm)로 돌아온다. 조준점 가림(총·팔만 껐다 켜서 잰 값): 대기·걷기·달리기·연사·옆걸음 연사·재장전 0초, 앉아 쏘기 150프레임 중 1프레임(5%).
- 1인칭 메시 88,211삼각형(팔 33k + 총·탄창 55k), `fp_detail.glb` 6.4MB.

힉스필드의 호스팅 Blender(3D Jutsu, `scene_builder_3d_*`)로 이 조립을 옮길 수 있는지 확인했다: 지금 판은 카탈로그 모델만 불러올 수 있고(사용자 파일 불가) 네트워크가 막혀 있어, 생성한 총·팔 GLB를 넣을 길이 없다. `/use-blender`는 로컬 Blender를 MCP로 모는 것이라 클라우드가 아니다.

### Blender를 걷어냈다: 힉스필드 모델을 받은 그대로 쓴다

새 모델을 예전 뼈대·예전 모양에 끼워 맞추는 과정(Blender 스크립트)에서 어긋남이 계속 생겼다(총 디자인, 탄창 자리, 총구 위치). 그래서 맵 소품과 1인칭 총은 **힉스필드에서 받은 GLB를 게임이 직접 불러** 쓴다. `tools/blender/`, `.blend` 원본, `map_kit.glb`, `fp_detail.glb`, `fp_rig.glb`는 지웠다(앞 절들의 Blender 이야기는 지나간 기록이다).

- **파일 용량만 줄인다**(`node tools/pack-generated.mjs <원본> <출력> [색 크기] [노멀 크기]`): 텍스처를 WebP로 줄이고 정점 자료를 meshopt로 압축한다. 삼각형은 하나도 줄이지 않는다. 원본 3~15MB → 0.15~1.2MB.
- **맵 소품**(`src/world/KitDirect.ts`, `public/assets/models/kit/*.glb` 15종): 컨테이너·상자·방벽·벽·서버 랙·제어대·정문·단말·탈출선에 더해, Blender로 짰던 기둥·난간·계단·하역장 상판·배경 타워·조명도 힉스필드로 새로 받았다. 게임이 하는 일은 방향(긴 쪽을 X로), 크기(충돌 상자에 맞춤), 원점(바닥 가운데)뿐이다. 표시등·화면은 겉그림의 밝고 진한 색을 셰이더가 빛나게 한다.
- **계단**: 세 단짜리 토막을 높이만큼 이어 놓는다. 단 하나하나가 충돌 상자의 단과 같은 자리에 온다(전에는 9단 모듈을 3단 계단에 줄여 넣어 어긋났다).
- **1인칭 총**(`src/render/FpDirect.ts`, `fp_gun.glb` · `fp_mag.glb` · `fp_arm.glb`): 총(탄창 뺀 것), 탄창, 팔을 각각 받았다. 뼈대가 없다: 총·탄창·왼팔·오른팔을 코드가 놓고, 재장전(총을 기울임 → 왼손이 탄창을 뽑아 내림 → 새 탄창을 들고 올라와 꽂음)도 코드가 움직인다. 손가락은 쥔 모양 그대로다. 배치 수치는 `FP_DIRECT`에 모여 있다. (이 방식은 그만뒀다: 아래 「1인칭: 두 팔이 총을 쥔 모델 하나로」.)
- **아직 Blender 산출물인 것**: 적과 주인공의 몸(`bot_rig.glb`, `player_rig.glb`). 뼈대와 걷기·달리기·옆걸음·앉기·쓰러짐 클립이 그 파일에 들어 있어서, 지우면 적이 움직이지 못한다. 힉스필드 리깅으로 바꾸는 것은 따로 할 일이다(다시 빌드할 스크립트는 이제 없다).

그리는 양(로컬, 800x600): 삼각형 66만~120만(전 15만~20만), 드로콜 152~369, 프레임 5.5~9.8ms. 받은 모델을 줄이지 않고 쓰는 값이다(벽 구간 하나가 3,864삼각형, 상자 4,298). 오토파일럿 3판 모두 승리(318~334초).

### 적도 힉스필드 모델 그대로: 리깅·동작까지 힉스필드에서

적의 몸은 Blender로 뼈대를 심고 동작을 구운 `bot_rig.glb`였다. 이제 **모델·뼈대·동작 전부 힉스필드에서 받은 것**을 쓴다(`bot_rig.glb`와 예전 `raven*.glb`, `pulse_rifle.glb`, `fp_arms.glb`는 지웠다).

1. 적 그림(`bot_detail_front.png`)을 참고로 총 없는 A자세를 그린다(`enemy_apose.png`).
2. Tripo H3.1 이미지→3D(30,000면, 정밀)로 모델을 받는다.
3. `node tools/face-forward.mjs`로 모델이 +Z를 보게 90° 돌린다(모양은 그대로). 받은 모델은 옆(+X)을 보고 있었고, 그대로 리깅하면 팔을 앞뒤로 잘못 알아 살이 찢어진다.
4. 힉스필드 3D Rigging에 넣는다(키 1.8m). 동작마다 한 번씩: Idle, Rifle_Charge(달리기), Walk_Forward_While_Shooting(사격 자세), Quick_Walk(걷기), Walk_Backward_with_Gun(뒷걸음), Shot_and_Fall_Backward.
5. `node tools/pack-character.mjs assets_src/higgs/enemy public/assets/models/enemy`: 대기 파일에서 모델(`enemy.glb`, 1.8MB)을, 나머지에서는 동작만(`enemy_<동작>.glb`, 20~70KB) 꺼낸다.

- 게임 쪽은 예전에 쓰던 '라이브러리 뼈대' 경로(`Bot.applyModel`)를 다시 쓴다: 뼈 이름(Hips, Spine, RightHand …)이 같다. 총은 주인공 총과 같은 모델을 따로 받아(`enemy_rifle.glb`) 오른손에 붙이고, 조준 방향으로 돌린 뒤 두 팔을 IK로 총에 붙인다.
- 색: 생성 모델은 주황 갑옷이다. 돌입병은 초록, 저격병은 자홍(색 채널 바꾸기), 보스는 붉게 물들인다. 총은 파란 판이 주황이 되게 채널을 바꾼다.
- 옆걸음 클립은 없다: 다리는 가는 쪽을 보고 상체가 조준 쪽으로 비튼다.
- 발 미끄러짐(디딘 발의 수평 속도, 중간값): 돌격병 0.46 m/s(몸 3.65 m/s), 돌입병 0.55 m/s(몸 4.56 m/s).
- 시행착오 둘: 첫 모델은 색 그림이 통째로 회색으로 나왔고(다시 생성), 방향을 확인하지 않고 동작 여섯 개를 한꺼번에 리깅시켜 전부 버렸다. 이제 한 건을 리깅해 화면으로 확인한 뒤에 나머지를 돌린다.

주인공의 3인칭 몸도 같은 방식으로 바꿨다(아래 「주인공 3인칭 몸도 힉스필드 모델 그대로」).

### 총구 화염 · 탄 · 피격 섬광도 생성 모델로

스프라이트(납작한 그림)였던 세 가지를 힉스필드에서 받은 입체 모델로 바꿨다(`fx_flash.glb`, `fx_bolt.glb`, `fx_impact.glb`, 각 2~3천 삼각형, 약 0.1MB).

- `Fx.setModels`가 방향과 크기만 맞춘다: 화염은 뾰족한 끝이 쏘는 방향, 탄은 굵은 머리가 날아가는 방향.
- 화염은 한 발마다 축을 돌려 총구에서 0.06초 동안 커지며 사라지고, 탄은 꼬리 띠 대신 입체 탄이 천천히 돌며 날아가고, 맞은 자리에는 가시 돋친 섬광이 0.16초 동안 터진다. 탄 머리의 둥근 빛과 화염 가운데의 작은 빛은 남겼다(먼 탄이 점 아래로 사라지지 않게).
- 색은 모델의 그림에서 밝기만 남기고 쏘는 쪽 색을 입힌다(내 탄 파랑, 돌격병 주황, 돌입병 초록, 저격병 자홍).
- 가산 혼합을 쓰지 않는다: 입체를 가산으로 그리면 밝은 배경에서 하얗게 타서 모양이 사라진다. 대신 색을 1.6배 밝게 줘서 블룸이 걸리게 했다.

오토파일럿 4판 모두 승리(324~335초).

### 주인공 3인칭 몸도 힉스필드 모델 그대로

마지막 Blender 산출물이던 `player_rig.glb`를 지웠다. 이제 게임에 Blender로 만든 파일은 없다.

1. 1인칭 팔 그림(`fp_arm.png`)과 적의 A자세 그림을 참고로 주인공의 A자세를 그린다(`player_apose.png`): 파란 갑옷, 흰 테두리, 청록 불빛.
2. Tripo H3.1 이미지→3D(30,000면, 정밀) → `player_apose.glb`. 색과 방향을 화면으로 확인하고 `tools/face-forward.mjs`로 +Z를 보게 돌린다.
3. 힉스필드 3D Rigging(키 1.8m). **대기 동작 한 건을 먼저 받아 게임에 넣고**, 조준을 위아래·좌우로 돌려 살이 찢어지지 않는 것을 본 뒤에 나머지를 주문했다: Rifle_Charge(달리기), Cautious_Crouch_Walk_Forward(앉아 걷기), Shot_and_Fall_Backward(쓰러짐).
4. `node tools/pack-character.mjs assets_src/higgs/player public/assets/models/player` → `player.glb`(1.8MB) + `player_<동작>.glb`(20~70KB).

`entities/PlayerBody.ts`를 새 뼈대에 맞춰 다시 썼다. 코드는 어떤 동작을 틀지 고르고, 동작이 알 수 없는 것만 더한다.

- **다리는 가는 쪽, 상체는 조준 쪽**: 옆걸음 클립이 없어서(라이브러리에 오른쪽 옆걸음이 없다) 적과 같은 방식이다. 전진과 뒷걸음 중 허리가 덜 비틀리는 쪽을 고르고, 좌우로 방향만 바꿀 때는 다리를 반 바퀴 돌리지 않고 걸음만 거꾸로 한다(`pickDir`).
- **뒷걸음 = 달리기 클립을 거꾸로**: 주인공은 뒤로도 초속 5.5m로 움직인다. 뒷걸음 클립(Walk_Backward_with_Gun, 디딘 발 초속 1.3m)은 2.6배로 틀어도 발이 초속 2.1m 미끄러졌다. 달리기를 거꾸로 틀면 0.5m다. 뒷걸음 클립은 받았지만 쓰지 않는다(파일도 싣지 않는다).
- **총과 두 손**: 총(`enemy_rifle.glb`, 색 그대로 파랑)은 카메라가 보는 곳을 향하고, 두 손은 2본 IK로 손잡이와 총열덮개로 간다. 질주하면 총이 오른손을 따라 내려간다.
- **재장전**: 무기의 진행률에 맞춰 왼손이 탄창으로 가서 빼냈다가 다시 끼운다(탄창 모델이 따로 움직이지는 않는다).
- **앉기**: 앉아 걷기 클립 하나로 한다. 멈추면 두 발을 디딘 순간의 자세로 모이고, 뒤로 가면 거꾸로 튼다. 클립이 상체를 깊이 숙여서 척추를 0.4rad 세운다. 머리 꼭대기는 1.42m로, 앉은 충돌 높이(1.25m)보다 높다.
- **쓰러짐**: 클립을 한 번 틀고 총은 오른손에 남는다.
- **공중 자세**: 힉스필드의 Fall2 클립(`player_air.glb`)을 쓴다. 클립 그대로는 무릎을 가슴까지 끌어안고 깊이 웅크려서, 서 있는 자세와 55:45로 섞고 척추를 조금 세운다(`AIR_MIX`, `AIR_STRAIGHTEN`). 무릎을 굽히고 뜬 자세가 된다.
- **옆걸음 클립은 받지 않았다**: 라이브러리의 총 든 옆걸음(Walk_Left_with_Gun)은 1.24초에 두 걸음인 조심스러운 걸음이라, 초속 5.5m로 움직이는 주인공에게 쓰면 뒷걸음 클립 때처럼 발이 미끄러진다. 달리는 속도의 옆걸음은 라이브러리에 없다. 주문 전에 미리보기 GIF로 걸음 주기를 확인했다.
- 청록 불빛(바이저·띠)은 겉그림의 청록색만 골라 빛나게 한다(`addCyanGlow`).

확인(개발 서버, 3인칭으로 켠 채 오토파일럿): 3판 모두 승리(354·339·340초), 몸 갱신 6만여 번에 오류·NaN 없음. 디딘 발의 미끄러짐(중간값)은 곧게 달릴 때 0.51 m/s, 방향 전환까지 넣은 한 판 전체로는 0.79 m/s다(다리가 가는 쪽으로 도는 동안 디딘 발이 함께 돈다).

### 벽 모델 다시 받기 · 1인칭 팔 숨기기

- **벽이 울퉁불퉁하던 원인**: Blender가 아니라 생성 모델 자체였다. 벽(`kit/wall.glb`)은 힉스필드 이미지→3D를 기본 품질, 3,864삼각형으로 받은 것이라 판이 녹은 것처럼 무르고, 아래쪽에 삼각형 하나가 튀어나와 있었다(겉그림을 빼고 회색으로 그려 보면 바로 보인다).
- 같은 그림(`prop_wall.png`)을 `geometry_quality: detailed`, 12,000면으로 다시 받았다(10,158삼각형, 0.29MB). 판이 평평하고 모서리가 곧다. 벽은 8m 모듈을 이어 쓰므로 한 화면의 삼각형이 63만~179만이 됐다(전에는 66만~120만).
- 기둥·문·랙·제어대·방벽·난간·데크·계단·단말·조명·탑·상자도 같은 방법으로 다시 받았다(아래 「나머지 소품 12종도 정밀 품질로」).
- **1인칭 팔**: 생성한 팔은 전완에서 평평하게 잘려 끝나는 모델이라, 잘린 끝이 화면 안에 떠 보였다. 한동안 두 팔을 숨기고 총만 그렸는데, 손이 총을 쥐지 않은 1인칭도 어색해서 아래 「1인칭: 두 팔이 총을 쥔 모델 하나로」로 바꿨다.

### 1인칭: 두 팔이 총을 쥔 모델 하나로

(이 방식은 그만뒀다: 팔이 총에 구워져 있어 자리가 어색했다. 아래 「1인칭: 총은 따로, 손은 뼈대로 쥔다」.)

총·탄창·팔을 따로 받아 코드로 맞춰 붙이던 것을 그만두고, **두 팔이 총을 쥔 채로 생성된 모델 하나**(`assets_src/higgs/fp_arms_detail.glb`, 97,316삼각형 → `public/assets/models/fp_held.glb` 1.6MB)를 그대로 쓴다. 전에 받아 둔 힉스필드 모델이라 새로 쓴 크레딧은 없다. `fp_gun.glb`·`fp_mag.glb`·`fp_arm.glb`는 지웠다.

- 오른손은 손잡이를, 왼손은 총열덮개를 쥐고 있고 팔은 어깨 쪽 끝까지 이어져 둥근 관절로 끝난다. 손과 총이 한 메시라 손이 총에서 뜨거나 어긋날 일이 없다.
- `render/FpDirect.ts`는 모델을 세우고(가는 쪽 끝이 총구) 자리만 잡는다: `FP_DIRECT.pos / rot / length`. 총구를 화면 가운데 쪽으로 0.1rad 돌리고 왼쪽을 0.1rad 낮춰서, 왼손과 전완은 화면에 들어오고 두 팔의 어깨 쪽 끝은 화면 아래로 나간다(4:3에 가까운 화면부터 21:9까지 확인).
- **재장전**: 손이 총에서 떨어질 수 없으므로 총을 조금 기울여 화면 아래로 내렸다가(탄창을 가는 동안은 보이지 않는다) 다시 올린다. 소리 신호(0.10 빼기, 0.66 끼우기, 0.82 장전 손잡이)에 맞췄다. 탄창이 따로 움직이는 모습은 없다.
- 조준점 가림: 재장전 전 구간을 0.04 간격으로 돌려 모델의 모든 정점을 화면에 투영했다. 조준점에서 가장 가까운 점까지의 거리는 화면 높이의 21%(서 있을 때)이고, 재장전 중에도 그보다 가까워지지 않는다. 처음 잡은 기울기는 총구가 6%까지 다가와서 고쳤다.
- 달리기 자세·반동·총구 화염 자리는 전과 같은 코드(`animateViewmodel`, 총구 지점)가 맡는다.

### 쓰러진 적이 계속 쌓이던 문제

한 판을 직접 돌려 보다가 찾았다. 죽은 적은 4초 뒤 목록에서 빠지지만 **몸은 장면에 그대로 남았다**: 한 판이 끝날 때 26구(약 95만 삼각형)가 누워 있었고, 「다시 시작」을 눌러도 지워지지 않아 판을 거듭할수록 쌓였다.

- 이제 목록에서 빠진 뒤 10초 동안 누워 있다가 2초에 걸쳐 바닥 아래로 가라앉고 장면에서 빠진다(`Mission.prune`, `CORPSE_STAY`, `CORPSE_SINK`). 새 판을 시작하면 남은 몸을 모두 지운다.
- 확인: 오토파일럿 3판 동안 장면의 뼈대 모델(살아 있는 적 + 쓰러진 적)은 많아야 5개였다(전에는 한 판 끝에 27개).

### 1인칭: 총은 따로, 손은 뼈대로 쥔다

팔과 총이 한 덩어리인 모델은 팔의 자리를 고칠 수 없었다. 이제 **총, 탄창, 팔을 따로** 받고, 팔은 힉스필드에서 리깅한 몸의 뼈대로 움직여 손을 총에 가져다 댄다(3인칭 몸이 총을 드는 것과 같은 방식). `render/FpDirect.ts`가 전부 맡는다.

| 파일 | 내용 | 크기 |
| --- | --- | --- |
| `fp_gun.glb` | 총(탄창 뺀 것). 예전 총 디자인에 조준기만 홀로그램 조준기로 바꾼 그림(`assets_src/higgs/fp_gun.png`) → Hunyuan3D v3 이미지→3D, 149,080삼각형 | 1.9MB |
| `fp_mag.glb` | 탄창. 전에 받아 둔 모델 그대로 | 0.14MB |
| `fp_body.glb` | 두 팔. 손을 쥔 모양으로 그린 A자세 그림(`player_grip.png`) → Hunyuan3D v3(15만 면) → 힉스필드 3D Rigging → 팔 뼈를 따라 움직이는 면만 남김(40,463삼각형) | 1.2MB |

- **그림**: 총은 사용자가 고른 대로 예전 파란 총 그대로에 조준기만 바꿨다(`gun5.png`, 조준기 참고 `gun5_sight_ref.png`). 몸은 주인공 A자세 그림에서 두 손만 바꿨다: 오른손은 손잡이를 쥔 주먹(검지는 방아쇠), 왼손은 받치는 C자 모양. 힉스필드 리깅에는 손가락 뼈가 없어서 손 모양은 모델에 빚어져 있어야 한다.
- **Tripo H3.1이 이날 계속 실패했다**(10만·15만·5만·4만 면, 여섯 건 모두 10~14분 뒤 실패하고 환불). 같은 그림을 Hunyuan3D v3로 받았다(2~3분, 건당 19크레딧). Hunyuan 모델은 Z가 위인 메시를 노드 회전으로 세워서 나온다: `tools/face-forward.mjs`가 그 회전을 정점에 구운 뒤 방향을 맞춘다.
- **팔만 싣는다**(`node tools/pack-fp-arms.mjs <리깅된 몸> <출력>`): 위팔·전완·손 뼈에 절반 넘게 묶인 정점의 삼각형만 남긴다. 뼈대는 전부 남는다. 몸통·머리·다리는 1인칭 화면에 들어올 일이 없다.
- **팔 풀기(2본 IK)**: 매 스텝 A자세에서 다시 푼다. 팔꿈치는 정해 둔 쪽(`elbowL`, `elbowR`)으로 벌어지고, 손목은 손의 자세(손바닥이 놓일 자리, 손가락이 뻗는 쪽, 손바닥이 보는 쪽)에 맞춘다. 손목이 돈 만큼의 60%는 전완이 함께 돈다.
- **손이 어떻게 생겼는지**: 손가락이 뻗는 쪽은 모델에서 찾는다(손목에서 손 정점들의 한가운데로). 손바닥이 보는 쪽은 모델에서 재어 `palmL`·`palmR`에 적어 두었다: 손등과 손가락 등에만 파란 판이 있어서, 겉그림이 파란 정점들의 한가운데에서 검은 정점들의 한가운데를 뺀 방향이 손등이다. 가장 얇은 방향을 찾는 식은 주먹 쥔 손에서 37도 틀렸다.
- **쥐는 자리**: 오른손은 손잡이(손바닥이 왼쪽을 본다), 왼손은 총열덮개를 아래에서 받친다(손바닥이 위, 엄지는 왼쪽 옆면, 네 손가락은 오른쪽 옆면). 총 공간의 자리는 총의 옆모습을 2cm 간격으로 잘라 잰 값에서 잡았다(손잡이 z 0.06~0.12, 총열덮개 밑면 y -0.053).
- **총의 자리**: 개머리판 뒷면이 화면 밖에 오도록 총 상자 중심을 (0.16, -0.165, -0.5)에 두고 왼쪽으로 0.12rad 돌려 왼쪽 옆면이 보이게 했다.
- **조준기 유리**: 이미지→3D는 비치는 것을 만들지 못해서, 받은 모델의 홀로그램 창은 희끄무레한 덩어리였다. 셰이더가 조준기 상자 안의 밝은 면을 어두운 유리로 칠하고, 쏘는 사람 눈에서 본 방향으로 빛나는 조준점(고리·가운데 점·눈금 넷)을 그린다(`FP_DIRECT.sight`, `addSightGlass`). 모델의 면은 건드리지 않는다.
- **재장전**: 총이 오른쪽으로 0.8rad 구르며 밑면이 왼쪽을 보고, 왼손이 총열덮개에서 탄창으로 가서 뽑아 화면 아래로 내렸다가 새 탄창을 들고 올라와 꽂는다(탄창은 쥔 순간의 손과의 상대 자리를 지키며 따라간다: 총에서 최대 43cm 떨어졌다가 0으로 돌아온다). 소리 신호(0.10, 0.66, 0.82)는 전과 같다.
- **확인**(개발 서버, 1000x700):
  - 조준점 가림(화면 가운데 28x28픽셀): 대기·걷기·달리기·재장전·앉기 모두 0초. 조준점에서 가장 가까운 총·팔 픽셀까지의 거리는 대기 때 화면 높이의 18.2%, 재장전 중 가장 가까울 때 12.1%다.
  - 오토파일럿 3판 모두 승리(322·347·336초). 1인칭 갱신 60,300번에 NaN 0, 오류 0.
  - 사격·질주·옆걸음·위아래 보기·앉기 화면을 실시간으로 돌려 손이 총에서 떨어지지 않는 것을 봤다.
- **남은 것**: 탄창이 바뀌는 순간은 화면 아래쪽 가장자리라 잘 보이지 않는다. 3인칭 몸과 적이 든 총은 예전 모양 그대로다. 모바일 세로 화면은 확인하지 못했다.

## 플레이테스트 (오토파일럿)

`src/dev/Autopilot.ts`는 사람처럼 플레이어를 조작한다(순찰 조준에서 임시 벡터가 겹쳐 항상 +z 벽을 보던 버그 수정)(반응시간·조준 오차·추적 속도·버스트·스트레이프·스킬 판단). 프로필: casual / average / good.
인게임 F8로 켜거나, 개발자 콘솔에서 시뮬레이션을 빠르게 돌려 밸런스 데이터를 뽑는다:

```js
// 콘솔: 난이도 버튼 클릭 → 시작 → 오토파일럿 → 60Hz 스텝을 직접 호출
document.querySelector('#difficulty [data-d="normal"]').click(); document.getElementById('btn-start').click();
game.setAutopilot('average'); for (let i = 0; i < 60 * 300; i++) game.step(1 / 60);
console.table(game.waveLog); console.log(game.player.stats);
```

2026-11-09 측정 (각 2회): EASY/casual 승리(사망 2) · NORMAL/average 웨이브 3~5 도달 · HARD/good 웨이브 2 전멸.
봇은 난이도별 공격 토큰(동시 사격 봇 수)과 피해 배율로 압박을 조절한다 (`src/data/difficulty.ts`).
